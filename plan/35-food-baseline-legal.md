# 35 · 맛집 맵의 합법적 베이스라인 — **폐기 (2026-09-12)**

> 사용자 결정으로 맛집 기능 전체를 제거했다. 아래 약관 조사(카카오 로컬 저장 금지, Google 지도 외 표시 금지, 네이버 검색 특약, NCP Maps 키 종류)는 다른 기능에서 재사용할 수 있어 남긴다.


2026-09-12. plan/34 §8 의 카카오 배치 수집은 **카카오 이용정책 위반**으로 확인됐다(아래 §0). 이 문서는 견적·계약 없이
**셀프서비스 API·공공데이터만으로** 맛집 맵의 바닥 데이터를 어떻게 만드는지 다시 설계한다.

### 1-5. 카카오의 역할
- 지도 타일·마커(우리 데이터)·`place_url` 딥링크(사용자가 카카오맵에서 상세를 보게 함) — 여기까지가 합법.
- 로컬 API 는 **사용자 검색창 실시간 보강**에만(결과를 저장하지 않고, 우리 대장과 이름+거리로 그 자리에서 매칭해 "우리 행" 을 열어준다).

## 2. 옮겨야 하는 것 (plan/34 대비)
1. **카카오 수집 중단 + 저장분 삭제**: `place_areas` 걷기(`crawl.places kakao`) 폐기, `places` 의 provider=kakao 행 7,665건 삭제(우리 리뷰·저장이 붙은 행은 공공 대장 행으로 재매칭 후 이전).
2. `places` 의 정체성을 **공공 키**로: `biz_key`(소상공인 상가업소번호) + `lic_no`(LOCALDATA 관리번호) + `google_place_id`(허용) + `ta_location_id`. `provider/provider_place_id` 는 제거.
3. 수집기는 그대로 **배치 시스템**(관리자 [맛집 지도] 3탭 유지): 출처 카드가 카카오 대신 **상가정보 / 인허가 / 위생등급 / 모범·안심·착한가격 / 관광공사** 로 바뀌고, 영역(중심·반경) 개념은 소상공인 반경 조회에 그대로 쓴다. 매월 전체 + 매일 변동분.
4. `nearby`/`search` 는 100% 우리 대장에서. Google/Tripadvisor 는 서랍 열 때만.
5. 카드·서랍의 "분류 아이콘" 매핑은 소상공인 소분류(247종) 기준으로 재작성.

## 3. 커버리지 기대치 (강남역 2km 기준 감)
- 존재·위치·업종: 소상공인+인허가 ≈ 카카오와 동급(전국 일반음식점 ~70만 + 휴게음식점 ~40만).
- 업력·영업상태·면적: 전수. 위생등급/모범/안심/착한가격: 각 수백~수천 곳(전국 수만).
- 메뉴 텍스트: 관광공사+착한가격+모범 합쳐 **일부**(수 %) — 나머지는 우리 사용자 제보(메뉴 사진·가격 입력)로 채우는 구조가 필요.
- 평점: Google 은 서울 도심 음식점 대부분에 존재(저장 불가·실시간).

## 4. 남은 확인
- 네이버 검색 API 약관 원문(저장·표시 조건) — 개발자센터에서 직접 확인.
- TMAP Open API 약관(저장 가능 여부).
- LOCALDATA 좌표 결측률(주소 지오코딩은 카카오 불가 → 공공 도로명주소 API/VWorld 지오코더로).

## 5. 다이닝코드는 어떻게 하는가 (2026-09-12 실측)
- 페이지 스크립트: 카카오는 **`dapi.kakao.com/v2/maps/sdk.js`(지도 SDK)만** 로드. 장소 데이터는 자체 엔드포인트(`/2018/ajax/*`), 사진은 자체 CDN(cloudfront/S3).
  즉 **카카오맵은 캔버스일 뿐, 데이터는 100% 자체 DB** — 정확히 우리가 §1 에서 설계한 구조.
- 자체 DB 의 출처(공개 자료): 네이버·다음·티스토리 **블로그 크롤링 + 자체 NLP**(점수·태그·"70점"), 자사 회원 평가·사진, 사장님 정보수정·폐업신고. 10년 넘게 쌓은 크롤링 DB 를 B2B 로 판매.
- 그들의 법적 기반은 "공개된 블로그를 크롤링해 인용·링크한다"는 **회색지대 관행**이다(야놀자 v 여기어때 2022 대법 무죄 — "이미 공개된 정보", 잡코리아 v 사람인 2017 — DB 권 침해 인정 4.5억). 우리가 같은 길을 가려면 그 리스크를 우리가 진다.

## 6. 추가 확인된 약관 (2026-09-12)
- **카카오 — 장소 ID·place_url 은 저장 가능**(devtalk [151335](https://devtalk.kakao.com/t/db-id/151335)): 자체 장소 DB 를 로컬 API 로 **매칭한 뒤 id 와 place_url 만** 저장 허용. "장소명·주소·좌표·전화·카테고리 등 그 외 모든 필드" 저장 금지. place_url 은 카카오맵 페이지로 보내는 용도로만, 우리 화면에 카카오 정보를 표시하지 않음, 모호한 매칭은 비워 둠. 자체 좌표를 카카오맵 마커로 찍는 것은 허용.
  → 우리 대장(공공 키) + `kakao_place_id`/`place_url` 컬럼만. 매칭은 "사용자가 검색창에서 그 가게를 열 때" 실시간으로(배치 매칭은 실시간 정책 위반 소지 — 카카오가 구조 소명을 요구).
- **네이버 검색 API 특약(2026-09-07 시행)**: 네이버 검색 결과를 **가공 없이 그대로** 보여주는 목적으로만, 결과 사이에 다른 내용 삽입·순위 변경 금지, AI 학습·답변·재판매 금지. → "블로그 언급량 점수" 같은 **집계·가공은 불가**. 허용되는 건 서랍 안의 "네이버 블로그 후기" 섹션에 검색 결과를 원형 그대로(제목·요약·링크) 실시간 표시하는 것뿐.
- 카카오 다음 검색 API 도 저장 금지 기조(책 검색 캐싱·블로그 검색 가공 문의들) — 동일 취급.

## 7. 구현 상태 (2026-09-12 저녁)
- **배포됨 (phase A)**: 0030 마이그레이션(카카오 행 삭제·Google 콘텐츠 컬럼 삭제·공공 키 컬럼 추가) / 수집기 `sbiz`(영역별, 2km 원 링으로 커버, 페이지 커서 재개) · `tour`(영역별, 상세 3콜, 30일 재조회) · `foodsafety`(전국 1,000건 페이지, 이름+주소 매칭) · `google`(ID 매칭만) / `matching`(이름 정규화·지점 접미사·숫자 가드·150m) / 읽기 `nearby`(sub·badge 필터, 원 전체 정렬 후 200+total)·`categories`(소분류 칩)·`search`(이름·소분류·메뉴)·`detail`(Google·네이버 블로그 **라이브, 10분 메모리 캐시**) / 사용자 메뉴 제보 API.
