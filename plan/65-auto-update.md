# plan/65 — 자동 업데이트는 Memora 에서

## 0. 요청 (2026-09-28)

자동 업데이트를 누르면 Memora 사이트에서 파일을 받아 제대로 업데이트되는가? 지금은 GitHub 주소로 보낸다.

## 1. 그때의 사정

- 0.8.0·0.8.1: [새 버전 받기]가 GitHub 릴리스 주소를 연다. 저장소가 비공개라 받을 수 없다. 이미 깔린 앱 안의
  주소라 서버에서 바꿀 수 없다.
- 0.8.2·0.8.3: 다운로드 센터를 브라우저로 열 뿐, 받아서 설치하지는 않는다.
- 안에 있던 electron-updater 는 GitHub 에서 찾아 늘 조용히 실패했다(0.8.2 에서 뺐다).

## 2. 한 것 (0.8.4)

- `src/main/update.ts`: `/api/downloads` 에서 최신 판과 이 컴퓨터의 설치 프로그램(`pickInstaller` — 윈도 .exe,
  맥 universal .dmg, 리눅스 .deb)을 받아, 메인에서 받는다(진행을 틀에). 크기와 **sha256 이 서버의 값과 같을 때만**
  설치한다.
  - 윈도: 설치 마법사를 조용히 `--updated /S --force-run`(electron-updater 가 NSIS 에 쓰는 인자 그대로). 사용자별
    설치라 관리자 권한을 묻지 않고, 끝나면 설치 프로그램이 앱을 다시 켠다.
  - 맥: 서명하지 않은 앱이라 Squirrel 을 쓸 수 없다. 앱이 닫힌 뒤 도는 스크립트가 이미지를 붙여 지금 자리의
    Memora.app 을 덮어쓰고(실패하면 옛 앱을 되돌림) 다시 연다. 덮어쓸 수 없는 자리면 이미지를 열어 준다.
  - 리눅스: `pkexec dpkg -i`(암호 창) 뒤 새 앱을 띄우고 닫는다. AppImage 로 쓰던 사람도 설치된 앱으로 옮겨 간다.
- 설정 [정보]: 새 판이 있으면 [업데이트] — 받는 동안 진행 막대와 %, 설치 중에는 "곧 다시 켜져요". 실패하면 그
  까닭과 [다운로드 센터]. 설정 아이콘에 점, 트레이에 [새 버전 x 로 업데이트].
- 새 판 확인은 로그인할 때·본창에 돌아올 때·잠에서 깰 때(여섯 시간에 한 번까지).

## 3. 확인

- 계약 테스트 23(설치 프로그램 고르기: 운영체제·칩·universal 이전 판·sha256 없는 파일은 설치하지 않음).
- 리눅스에서 앱을 0.8.0 으로 속여 [업데이트]: 0.8.3 을 새 판으로 알아보고, Memora 에서 .deb 를 받아 sha256 이
  서버와 같음을 확인(설치 단계는 이 서버를 바꾸므로 `MEMORA_UPDATE_DRYRUN` 으로 멈춤).
- 윈도·맥의 설치 단계는 이 환경에서 돌려 보지 못했다. 윈도는 electron-updater 와 같은 인자라 믿을 만하고, 맥은
  실기에서 한 번 봐야 한다.

## 4. 알아 둘 것

- 0.8.4 부터 스스로 업데이트한다. 그 전 판(0.7.0~0.8.3)은 스스로 올라올 수 없으니, 한 번은 다운로드 센터에서
  0.8.4 를 받아 설치해야 한다.
