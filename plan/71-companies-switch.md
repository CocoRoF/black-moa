# plan/71 — 기업 기능을 관리자가 한 번에 끈다

## 0. 요청 (2026-09-28)

기업 정보와 기업 관련 기능 전부를 끌 수 있게. 관리자 메뉴에서 끄면 커뮤니티에도, 개인 프로필에도 나오지 않아야 한다.
이미 넣어 둔 것도 보이지 않고, 새로 넣는 것도 불가능하게 — [내 정보]에서 넣을 수 없도록.

## 1. 한 것

**스위치 하나:** [관리자 → 기업정보 → 수집 설정] 맨 위 [기업정보 기능 · 기업정보 사용] (`companies.enabled`, 기본 켬).
수집(자동 수집·[수집])과는 따로다. 꺼도 관리자는 목록을 모으고 볼 수 있다. **저장된 것은 지우지 않는다.** 다시 켜면
소속·회사 인증·공개 범위가 그대로 돌아온다.

`services/companies/switch.py` 하나가 판단한다(`enabled`·`require`·`gate`·`PROFILE_FIELDS`). 화면만 감추면 옛 앱이나 직접
부른 요청이 계속 쓰고, 다른 사람의 프로필 응답에 소속이 실려 나가기 때문에 서버가 막고 걸러 낸다.

| 끄면 | 어디서 |
|---|---|
| 기업 페이지·리뷰·비교·관심 기업·회사 인증 요청 전부 `403 companies_disabled` | `api/companies.py`·`api/company_verify.py` 라우터에 `Depends(CO.gate)` |
| 프로필 저장이 소속·인증 칸(값과 공개 범위)을 버린다. 합치기라 저장된 값은 남는다 | `PF.update` (내 정보 저장·비서의 `profile_update` 둘 다) |
| 내 정보·회원 프로필·공개 페이지(OG 포함)·비서의 [지식] 탭·지시문 미리보기에 소속 없음 | `PF.shown()` — 기업 칸을 뺀 읽기 전용 사본 `ProfileView`. 행을 고치지 않는다 |
| 비서의 지시문(프로필 블록·첫 줄 소개)·`profile_get` 에 소속 없음 | runner·runtime 이 `PF.shown` 을 쓴다 |
| 비서의 `profile_update` 는 소속을 저장하지 않고 그렇다고 말한다(`not_saved`) | `profile_tools.py` |
| 비서의 `company_lookup` 도구 없음 | `requires_feature="companies"` + 런타임 기능 `feature:companies`(지문에 들어가 바뀌면 다시 세운다) |
| 광장의 글쓴이 줄은 직함만 | `community.authors_for` |
| 같은 회사 동료를 아는 사람으로 치지 않는다 | `people.viewer_level` |
| 채용공고 목록·집계·등록·마감 전부 닫힘(§3 에서 바로잡음 — 처음엔 기업 연결만 뺐다) | `api/community.py` 의 `JOBS_GATE` |
| 인박스·아침 메일·알림 규칙에서 관심 기업 소식이 빠지고, 새로 생기지도 않는다 | `inbox.hidden_kinds`, `notify_followers`, `build_digest`, `/api/notifications/channels` |
| 비서의 사람 찾기가 소속으로 찾지 않는다 | `relay` 프로필 검색 |
| 인기 순위·매일 자동 수집 멈춤 | worker `companies.rank`·`companies.refresh` |

**웹:** `/api/auth/status` 의 `companies` → `useCompanyFeatures()`(알기 전에는 감춘다).
커뮤니티 [기업정보] 탭(웹의 틀과 PC 앱의 문 탭 둘 다 `useCommunityNav`), 기업 페이지(주소로 들어와도 `CompaniesGate` 가
"기업정보를 쓰지 않고 있어요"), 공고의 기업 카드와 기업 고르기(회사 칸은 그냥 입력), 내 정보의 소속 칸과 회사 인증 카드,
광장 이름 미리보기의 소속, 지난 대화의 기업 카드와 사람 찾기 결과의 소속. 관리자 스위치를 바꾸면 그 화면의 탭·프로필도
곧바로 다시 읽는다.

남긴 것(기업 기능이 아님): 인맥 메모의 회사(`attrs.company`), 방문자가 스스로 밝힌 회사, 광장의 "회사생활" 게시판,
[내 정보 → 내보내기](내 데이터 전부).

## 3. 채용공고도 같이 (2026-09-28, 사용자 지적)

"기업 정보와 채용 정보는 같이 움직이는 것." 처음에는 채용공고를 그대로 두고 공고의 기업 연결만 뺐다 — 끄고 나서도
[채용공고] 탭과 공고 쓰기가 살아 있었다.

- 서버: `/api/community/jobs` 목록·집계·등록·마감이 같은 문(`CO.gate`)을 지난다. 분류표(`/jobs/taxonomy`)는 프로필의
  직무·지역·업종 고르기도 쓰므로 연다. 공고의 기업 카드만 빼던 반쪽 처리(`_job_out(companies=)`, `create_job` 의 분기,
  웹 `JobsBoard` 의 회사 칸 분기)는 걷었다.
- 웹: 커뮤니티 [채용공고] 탭도 감추고(`useCommunityNav` 의 `COMPANY_TABS`), `/app/community/jobs` 도 `CompaniesGate`.
- 문구: 관리자 [기업정보·채용공고 기능 · 기업정보·채용공고 사용], 닫힌 화면 "기업정보와 채용공고를 쓰지 않고 있어요".
- 확인: `test_jobs_move_with_companies`(끄면 네 길 403·분류표 200, 켜면 올린 공고 그대로), 전체 640. 운영(사용자가 꺼 둔
  상태 그대로): 채용 API 3곳 403, 분류표 200, 커뮤니티 탭에 채용공고·기업정보 없음, 채용공고 주소 닫힘, 관리자 스위치
  이름·꺼짐 — 8/8.
