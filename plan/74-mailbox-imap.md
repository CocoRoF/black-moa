# plan/74 — 메일함은 IMAP + 앱 비밀번호로 (Gmail 제한 범위를 쓰지 않는다)

## 0. 배경 (2026-09-29)

Google OAuth 인증을 준비하다 보니, Gmail 읽기(`gmail.readonly`)가 Google 의 **제한 범위**였다. 외부 사용자에게 열려면
매년 제3자 보안 평가(CASA)를 받아야 한다(기본 등급 연 $540~$1,800). 사용자: "사용자가 자기 이메일을 읽는 건데 왜?
다른 방법을 제대로 검토하고, 없으면 빼라."

## 1. 검토

| 방법 | 판단 |
|---|---|
| gmail.metadata(머리글만) | 이것도 제한 범위다. 소용없다 |
| gmail.addons.current.message.* | 민감 범위지만 Gmail 화면 안의 부가기능(Workspace 애드온)에서만 쓴다. 비서가 메일함을 훑는 모양이 아니다 |
| 검증 없이 사용(테스트 모드·미검증 앱) | 사용자 100명 한도가 있고, 테스트 모드는 7일마다 연결이 끊긴다. 정식 서비스로는 쓸 수 없다 |
| 사용자 본인의 Google Cloud 프로젝트 | 사용자마다 콘솔에서 앱을 만들어야 한다. 대중 서비스로는 무리다 |
| 메일 자동 전달(우리 주소로) | 받는 메일 설비가 필요하고, 새 메일만 온다. 나중에 덧붙일 수 있다 |
| **IMAP + 앱 비밀번호** | Google API 를 거치지 않아 그 평가 대상이 아니다. Gmail(2단계 인증 계정의 앱 비밀번호), 네이버, 다음, 카카오 메일이 같은 길로 붙는다. **채택** |

## 2. 한 것

- `services/imap_mail.py`
  - 받은편지함만 **읽기 전용**으로 연다(읽음 표시도 바꾸지 않는다).
  - 최근 30일, 한 번에 새 메일 200통, 연결당 2,000통까지 둔다. 본문은 열 때 읽고, 미리보기만 둔다.
  - 256KB 가 넘는 메일은 머리글만 가져온다.
  - Gmail 은 `X-GM-RAW` 로 광고·소셜 탭을 뺀다. UIDVALIDITY 가 바뀌면 처음부터 다시 가져온다.
  - 앱 비밀번호는 암호화해서 `access_token_enc` 에 둔다. 먼저 로그인해 보고 되면 저장한다(틀린 비밀번호는 저장하지
    않는다). 앱 비밀번호의 띄어쓰기는 지운다.
  - 나중에 로그인이 실패하면 연결을 만료로 적고 사용자에게 알린다.
  - 서버 주소는 공인 주소(`safe_http._public_ips`)만, 포트는 993 만 받는다. 확인한 IP 로만 접속한다(`_Pinned`) —
    DNS 가 바뀌어 내부망으로 새는 것을 막는다.
- `services/mail.py`: 등록표를 `{"imap"}` 으로 바꿨다. 이름은 `label_for`(Gmail, 네이버 메일…)로 붙인다.
  `CN.sync_all` 이 imap 을 먼저 처리한다.
- API: `POST /api/mail/accounts` (10분에 8회 — 남의 메일 서버에 비밀번호를 대 보는 통로가 되지 않게),
  `DELETE /api/mail/accounts/{id}` (앱 비밀번호와 가져온 메일을 지운다).
- Google 쪽:
  - `gmail_read` 기능, `gmail.readonly` 범위, Gmail 동기화 코드를 제거했다.
  - 설정에 남아 있는 모르는 기능은 내주지 않는다(`offered`).
  - Google 에는 캘린더와 연락처(민감 범위)만 청한다.
- 화면 [메일]:
  - 메일함 연결 창: Gmail·네이버·다음·카카오·기타를 고르면 서비스별 앱 비밀번호 안내와 바로 가는 링크를 보여 준다.
    기타는 서버 주소를 받는다.
  - 메일함 줄마다 지금 가져오기, 다시 연결, 연결 해제. [메일함 추가]로 여러 개를 이을 수 있다.
  - [연동] 화면의 "메일로" 바로가기는 뺐다.
- 처리방침:
  - 연동 표의 Gmail 줄을 메일함(IMAP)으로 바꿨다(연결 정보, 받은편지함 머리글·미리보기).
  - 제8조에 "Google API 로 Gmail 에 접근하지 않음"을 넣었다(영문 요약 포함).
  - 국외 이전 표의 Anthropic 항목에 "연결한 메일과 일정"을 넣었다.

## 3. 확인

- 백엔드 655 통과. `test_imap_mail.py`(가짜 IMAP 서버)로 본 것:
  - 틀린 비밀번호는 저장하지 않고, 띄어 쓴 앱 비밀번호도 받는다.
  - 가져오기: 한글 제목, EUC-KR 본문, 큰 메일은 머리글만, 안 읽음 표시. 같은 메일을 두 번 넣지 않는다.
  - 본문을 읽는다. 비밀번호가 바뀌면 만료되고, 다시 넣으면 같은 줄이 살아난다. 해제하면 모두 지운다.
  - 내부 주소는 막는다. Google 은 Gmail 을 청하지 않는다.
- 운영:
  - Google 연동 기능이 일정 읽기, 일정 관리, 연락처뿐이다.
  - 실제 imap.gmail.com 과 imap.naver.com 에 접속해 틀린 비밀번호로 `imap_auth_failed` 가 나온다(연결 경로가 산다).
  - 내부 주소는 `imap_host_blocked`.
  - 메일 화면과 연결 창(PC·휴대폰)을 눈으로 봤다.

## 4. 남은 것

- Google Cloud 콘솔 [데이터 액세스]에서 `gmail.readonly` 를 지워야 심사가 제한 범위(CASA)로 가지 않는다.
- 캘린더와 연락처는 민감 범위다. 심사 때 범위별 사유와 시연 영상이 필요하다.
