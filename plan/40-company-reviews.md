# 40. 기업정보 개편 — 대시보드 · 검색 · 기업 페이지 · 리뷰

2026-09-13. plan/33 의 디렉터리는 "5,093개를 목록으로 다 보여주는" 화면이었다. 이 문서는 그것을
**들어가면 볼 것이 있는 대시보드**, **검색으로 닿는 결과 화면**, **기업마다의 상세 페이지(통계·리뷰·
연봉·면접·복지·채용·커뮤니티)** 로 바꾼 기록이다. 잡플래닛의 구조를 참고했고, 데이터는 여전히
국가·거래소 공개 데이터 + **우리 회원이 남긴 리뷰**뿐이다(스크래핑 없음, plan/33 §7 그대로).

## 1. 세 화면

| 화면 | 경로 | 내용 |
|---|---|---|
| 대시보드 | `/app/community/companies` | 검색창 · 인기 기업(12) · 연봉 언급 TOP 3 · [내 직군 / 팔로우 / 내 회사] · 큐레이션 선반 · 방금 올라온 리뷰 |
| 검색 결과 | `…/companies?q=` | 탭 [전체 / 기업 / 채용 공고 / 커뮤니티 글]. 전체 = 큐레이션 선반 + 기업 6 + 공고 6 + 글 6. 기업 탭 = 업종·지역·시장·정렬 + 페이지 |
| 기업 페이지 | `…/companies/{id}` | 밴드(로고·평점·업종·채용 중) + 탭 [개요 / 리뷰 / 연봉 / 면접 / 복지 / 채용 / 커뮤니티]. 개요 = 전체 통계(재직 연도 필터·5축·추천율/CEO/성장 링·연도별 트렌드) + 기업 정보 + 같은 업종 |
| 리뷰 쓰기 | `…/companies/{id}/review` | 한 사람당 한 회사에 하나(다시 쓰면 수정). 이름은 안 남고 직군·재직 상태·연도만 |

## 2. 한 테이블, 여러 탭

리뷰는 **`company_reviews` 한 행**이다: 총평 + 5축(복지/급여·워라밸·사내문화·승진 기회·경영진), 장점/단점/
경영진에게, 추천·CEO 지지·성장 전망, 그리고 선택으로 **연봉(만원)·경력**, **면접(난이도·결과·질문·과정)**,
**받은 복지(카탈로그 코드)**. 연봉·면접·복지 탭은 이 표를 다른 조건으로 읽은 것이다. 폼이 셋이 아니라
하나인 이유이고, 한 사람의 리뷰가 세 탭에 동시에 기여하는 이유다.

저장할 때 본문에서 **화제(topics)** 를 뽑아 둔다(연봉·복지·워라밸·승진·문화·경영진·성장). "연봉 이야기가
많은 회사"는 그래서 정규식이 아니라 인덱스 조회다.

## 3. 숫자는 쓸 때 계산한다

리뷰가 저장·삭제·숨김될 때 그 회사의 `stats`(축 평균, 추천율, CEO 지지율, 성장 기대율, 연도별, 직군별,
연봉 중간값·경력대, 면접 n·난이도·합격률, 복지 언급 수, 현/전직원) 와 `rating`·`review_count`·`tags` 를
같은 트랜잭션에서 다시 쓴다. 대시보드와 검색은 리뷰를 집계하지 않고 companies 행만 읽는다.

**인기**(`popularity`)는 한 곳에 정의한다: `ln(1+주간조회)×3 + 팔로우×2 + 리뷰×4 + 채용중×1.5 + 시장등급
(유가 1 / 코스닥 0.6 / 코넥스 0.3) + 홈페이지 0.2 + ln(1+임직원)/4`. 워커가 매시간 전 회사를 다시 매기고
(`companies.rank`, UPDATE 네 문장), 조회·팔로우는 그 사이에 작은 증분을 준다. 리뷰가 하나도 없는 첫날에도
순서가 있고, 사람들이 보기 시작하면 곧 그쪽으로 기운다.

## 4. 비어 있지 않게

- 연봉 TOP: 리뷰가 3개 회사에 못 미치면 **연봉을 적은 채용 공고**로 채운다(출처 표시).
- 큐레이션 선반: 평가형(승진·연봉·워라밸·분위기)은 리뷰 2개 이상·3.5점 이상인 회사가 3곳은 있어야 뜬다.
  그 전엔 **채용 중 / 이번 주 많이 본 / 새로 상장한** 선반이 페이지를 채운다 — 거래소·공고가 이미 아는 사실이라 정직하다.
- 내 직군: 프로필 직무가 없으면 고르러 가는 안내. 있으면 회사마다 **이유**를 단다(내 직무 채용 n건 / 같은 직군
  리뷰 n개 / 내 업종).
- 내 회사: 프로필 회사명이 상장사 표시명과 정확히 같을 때만 연결(잘못 붙이느니 안 붙인다).

## 5. 사람 쪽 규칙

- 리뷰는 **익명**: 응답에 작성자 식별자가 없다. 바이라인은 직군·재직 상태·연도.
- 한 사람 한 회사 하나(UNIQUE). 시간당 5개. 인증 메일 규칙은 커뮤니티 글과 같다.
- 도움돼요는 게시글 좋아요와 같은 방식(유니크 행이 결과를 정함), 본인 리뷰에는 불가.
- 신고는 커뮤니티 신고함으로 간다(`target_type=review`). 관리자가 숨기면 그 회사 숫자에서 빠지고, 숨겨진
  리뷰는 다시 쓸 수 없다.
- 폼 검증은 필드를 이름으로 돌려준다(`review_too_short {field}`). 모르는 코드는 거부가 아니라 버린다 —
  오래된 폼도 저장은 돼야 한다.

## 6. 로고

회사 로고는 가져올 곳이 없다(서버가 남의 사이트를 읽지 않는다는 규칙). 처음엔 이름별 색 타일을 썼으나
사용자 결정으로 **건물 글리프 하나**(기본 Company 마크)로 통일했다 — 이름이 회사를 구분하고, 마크는 조용히 있는다.

## 8. 평가는 별점이 아니라 질문이다 (2026-09-14)

사용자 지적: "복지/급여·워라밸·사내문화·승진·경영진 별점 5개 + 추천/CEO/성장" 은 잡플래닛 그대로다.
그래서 **평가 모델 자체**를 바꿨다. 리뷰어는 별을 고르지 않고, 직장 생활에서 실제로 궁금한 것에
**말로 된 보기**로 답한다(`services/companies/questions.py`, 답은 `company_reviews.answers` JSONB).

| 영역 | 질문(굵게 = 필수) | 보기 |
|---|---|---|
| 보상 | **급여는 업계와 비교해** · 인상과 성과급은 · 복지는 | 낮아요/비슷해요/높아요/최상위 · 거의 없어요/물가 수준/성과대로 · 기본만/있을 건/촘촘 |
| 시간 | **주에 실제로 일하는 시간은** · 야근은 · 휴가는 · 유연근무 | 40↓/40~45/45~52/52↑ · 거의 없음/월 몇 번/주 1~2회/거의 매일 · 눈치 없이/조율하면/어려워요 · 재택/자율출퇴근 |
| 사람 | **소통은** · 동료들은 · 실수나 다른 의견을 말해도 · 회식·행사는 | 수평/반반/수직 · 배울 게 많아요/무난/아쉬워요 · 괜찮아요/상황 봐서/어려워요 · 자유/가끔/잦고 부담 |
| 성장 | **승진은** · 승진의 기준은 · 배울 기회는 · 이직할 때 이 경력은 | 빨라요/보통/느려요/막힘 · 성과/연공/불투명 · 많아요/있어요/적어요 · 커요/보통/별로 |
| 경영·안정 | **경영진을** · 회사의 방향은 · 고용은 · 회사의 앞날은 | 믿어요/보통/못 믿어요 · 명확/흐릿/없음 · 안정/보통/불안 · 성장/그대로/어려워짐 |

| 누구에게 | 이런 분께 맞아요(≤3) · 안 맞아요(≤2) | 성장 욕심/안정/워라밸/보상 최우선/자율/체계/주니어/경력자 |

- 보기마다 점수가 있어 **영역 점수 = 답한 질문의 평균**, 총점은 "다시 올래요" 에서, 추천은 꼭/아마도,
  CEO 지지는 "경영진을 믿어요/못 믿어요" 에서 나온다. 오각형·비교표·인기 순위는 그대로 돈다.
- 회사 통계에 **`facts`**(질문별 보기 카운트)와 `answered` 가 추가되고, 페이지의 "일하는 모습" 은
  질문마다 **가장 많은 답과 비율**("주 실근무 45~52시간 60%") + 분포 띠, 그리고 "이런 분께 맞아요/안
  맞아요" 상위 태그를 보여준다. 비교표에도 6줄이 들어간다. 리뷰 카드는 답을 칩으로 보여준다.
- 별점으로 남긴 옛 리뷰는 그대로 유효하다(`answers` 없음 → 옛 필드 경로, 카드에 "평가" 접기만 남음).
- 영역 이름도 우리 말로: 보상 · 시간 · 사람 · 성장 · 경영·안정.

## 9. 대시보드는 우리 다섯 영역으로 (2026-09-14)

"연봉 언급 TOP 회사" 같은 남의 구성 대신, 리뷰가 묻는 다섯 영역이 곧 대시보드의 축이다. 인기 기업 다음에
**보상·시간·사람·성장·경영·안정 TOP 회사** 판이 하나씩 놓인다(`home.areas`, `area_top`). 판의 한 줄 = 순위 ·
회사 · 그 영역 점수 · **그 영역의 대표 사실**(필수 질문의 최다 답과 비율: 급여 업계 대비 / 주 실근무 / 소통 /
승진 속도 / 경영진 신뢰) · 리뷰 수. 리뷰가 하나라도 있으면 오르고 수를 같이 적으니 한 사람의 5.0은 한 사람의
5.0으로 읽힌다. 비어 있는 영역은 "첫 리뷰가 올라오면 채워져요" 로 솔직하게 비워 둔다. 연봉·채용·상장 선반은
대시보드에서 뺐다(검색 결과의 큐레이션 띠는 남음).

## 10. 내 회사 인증은 회사 메일로, 도메인은 홈페이지에서 (2026-09-14)

"어느 회사에서 일하세요"를 믿을 근거는 **그 회사 메일함을 열 수 있다**는 것 하나다. 코드를 보내 확인하는 부분은
가입 이메일 인증과 같다(`accounts.start_email_verification` 과 같은 6자리·`sha256(user_id:code)`·15분·5회). 어려운
쪽은 **주소의 도메인이 어느 회사 것인지**다. 세 갈래로 답한다(`services/companies/domains.py`, 표 `company_domains`).

1. **홈페이지**: 거래소가 상장사 홈페이지를 준다(운영 2,586곳). 회사 메일은 거의 언제나 홈페이지와 같은 *등록 도메인*을 쓴다.
   `www.samsung.com/sec` → `samsung.com`, `mail.abc.co.kr` → `abc.co.kr`(작은 공용 접미사 표: co/or/ne/re/go/ac.kr 등).
   호스팅·플랫폼(cafe24, imweb, notion.site, blog.naver…)과 공개 메일 도메인은 회사 것이 아니므로 버린다.
   `companies.rank` 시간마다 `sync_from_homepages` 가 `ON CONFLICT DO NOTHING` 으로 채운다(홈페이지를 콘솔에서 고치면 다음 시간에 반영).
2. **관리자**: 콘솔 [기업정보 › 회사 인증] 에서 회사별 도메인을 넣고 뺀다(홈페이지가 없거나 다른 회사).
3. **회원 제안**: 아무도 모르는 도메인이면 코드를 확인한 뒤 회사를 고르게 한다. 그 매핑은 `pending` 으로 남고, 관리자가 승인하거나
   **세 명**이 같은 회사라고 하면 저절로 `confirmed` 가 된다. 본인은 바로 "인증한 회사"가 되지만 리뷰의 **재직 인증** 배지는
   매핑이 confirmed 일 때만 붙는다(`verified_for`). 한 사람의 주장으로 회사 배지가 생기지 않게 하는 선.

**한 도메인에 여러 회사**(그룹사가 `samsung.com` 을 함께 쓰는 경우)는 코드 확인 뒤 후보 중 하나를 고른다(`state: choose`).
**개인 메일**(gmail, naver, daum, kakao.com 등 45개)은 처음부터 거절한다. 주소는 저장하지 않고 해시와 마스킹만 남기며,
같은 메일함으로 두 계정을 인증할 수 없다(verified 행의 `email_hash` 부분 유니크). 시간당 5회 발송, 코드 5회 오답이면 새 코드.

효과: 프로필 `company_id / company_verified_at / company_domain` 은 **잠긴 필드**(`profile.LOCKED_FIELDS`)라 프로필 PUT 으로는
못 쓰고 인증 흐름만 쓴다. 소속 칸은 인증한 회사 이름으로 고정되고, 대시보드 [내 회사] 는 이름 매칭보다 인증을 우선하며,
리뷰 저장 시 `company_reviews.verified` 가 찍혀 카드에 "재직 인증" 배지와 통계 `verified_n` 이 생긴다. 비서 프롬프트에는
`company: 삼성전자 (회사 이메일로 인증됨)` 으로 한 줄만 들어가고 id·도메인은 들어가지 않는다. 회원 프로필 페이지도
인증 사실만 본다(`company_verified_at`), 메일 주소는 어디에도 나가지 않는다.

API: `GET/POST start/POST confirm/DELETE /api/users/me/company`; 관리자 `/api/admin/companies/domain-claims`(정적 경로를
`/companies/{id}` 앞에), `/companies/{id}/domains`. 화면: `owner/CompanyVerifyCard.tsx`(소속 칸 → 3단계 대화상자: 주소 → 코드 → 회사),
`admin/Companies.tsx` 의 [회사 인증] 탭.
