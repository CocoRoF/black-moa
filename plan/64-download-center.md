# plan/64 — 다운로드 센터

## 0. 요청 (2026-09-28)

Memora 웹의 인박스·관리자 아래에 [다운로드 센터]를 두고 앱을 받을 수 있는 페이지를 만든다. 앞으로 GitHub 에서
릴리스된 것은 모두 기본적으로 Memora 에서 받을 수 있어야 한다.

## 1. 사정

- 저장소가 **비공개**다. GitHub 의 설치 파일 주소는 로그인 없이 404 — 사람은 GitHub 에서 받을 수 없다.
- 그러니 Memora 서버가 릴리스를 읽어 설치 파일을 **제 저장소에 옮겨 두고** 거기서 내어 줘야 한다.
- 비공개 저장소를 읽으려면 토큰이 있어야 하는데, 가진 것은 모든 권한(저장소 삭제·조직 관리까지)의 개인 토큰뿐이다.
  그것을 운영 서버에 두지 않는다.

## 2. 한 것

**서버**
- `app_releases`·`app_release_assets`(0081): 앱 릴리스(태그 `desktop-v*`)와 설치 파일(.exe·.dmg·.AppImage·.deb,
  업데이트 부속은 뺌)의 거울. 파일은 하나씩(`downloads.mirror`, 동시에 하나) GitHub 에서 받아 크기를 맞춰 보고
  SeaweedFS 에 올린다. GitHub 에서 사라진 릴리스는 목록에서 빼고 파일도 지운다.
- `GET /api/downloads`(로그인): 받을 수 있는 릴리스, 최신이 먼저. 파일 주소는 서명된 주소(세 시간) — 링크는
  로그인 토큰을 싣지 못한다. `GET /api/downloads/assets/{id}?t=`: 이어받기(Range)·처음부터 받은 것만 셈.
- **토큰은 CI 가 건넨다.** 릴리스 워크플로가 공개 직후 `memora-downloads`(재사용 워크플로)를 부르고, 그 잡의
  `GITHUB_TOKEN`(이 저장소 읽기, 잡이 끝나면 무효)을 `POST /api/downloads/ci` 로 건넨 뒤 다 옮겨질 때까지 기다린다.
  열쇠(`downloads.ci_key`)는 저장소 시크릿 `MEMORA_RELEASE_KEY` 와 같다. 서버는 다 옮기면(아니면 두 시간 뒤)
  그 토큰을 지운다. 토큰 없이 CI 로 알려 오는 동안에는 10분마다 두드리지 않는다.
- 관리자가 읽기 전용 토큰(Contents: Read)을 넣으면 10분마다도 확인한다.

**웹**
- 사이드바 발치: 인박스 · 관리자(관리자만) · **다운로드 센터**(모두), 휴대폰 시트에도.
- 다운로드 센터: 이 컴퓨터의 운영체제(Mac 은 크롬 계열이면 칩까지)에 맞는 파일을 크게, 나머지는 아래에. 이번
  버전의 노트(릴리스 본문), 운영체제별 설치하는 법, 이전 버전. 휴대폰이면 컴퓨터에서 열라고.
- 관리자 [다운로드 센터]: 저장소·태그 머리·토큰·CI 연결 여부, 마지막 확인, 옮겨 둔 파일마다 상태·크기·받은 횟수.

**앱 (0.8.2)**
- 새 판 확인을 GitHub(비공개라 늘 실패하던 electron-updater)에서 Memora 로: 로그인할 때·여섯 시간마다
  `/api/downloads` 의 최신 판과 비교해, 새것이면 설정 [정보]와 트레이에 알리고 [새 버전 받기]가 다운로드
  센터를 연다.

## 3. 겪은 것

- **릴리스 노트가 커밋 메시지였다.** `actions/checkout` 이 주석 달린 태그를 커밋만 가리키는 태그로 받아 와,
  `gh release create --notes-from-tag` 가 커밋 메시지(Co-Authored-By 까지)를 노트로 썼다(0.7.0~0.8.1). 다운로드
  센터에 그대로 보여서 알았다. 태그를 다시 받아 본문을 노트로 쓰게 고치고 지난 셋을 바로잡았다.
- 서버의 백엔드 컨테이너는 읽기 전용이라 `docker cp` 가 안 된다. 열쇠는 표준 입력으로 넣었다.

## 4. 확인

- 서버 6(설치 파일만·옮기기 전엔 안 보임·서명 주소·이어받기·416·셈·다른 파일의 서명 거절·사라진 릴리스·관리자
  설정·CI 토큰 사용 후 삭제) + 전체 614 통과.
- 운영: 지난 세 릴리스 15개 파일을 CI 경로로 옮겼고, Memora 에서 받은 .deb 가 GitHub 의 것과 sha256 이 같다
  (약 19MB/s). CI 토큰은 다 옮긴 뒤 지워졌다.

## 5. 다듬기 (같은 날)

- 다운로드 센터에서 버전 설명(업데이트 기록)을 뺐다. 이전 버전은 받을 파일만 펼쳐서 보여 준다.
- 소개 한 줄: "언제 어디서든, 당신의 비서와 함께하세요."
- **운영체제마다 설치 프로그램 하나.** 윈도는 설치 마법사(.exe), 맥은 Apple 칩·Intel 을 한 파일에 담은
  universal .dmg(0.8.3 부터, 이전 판만 칩마다 둘), 리눅스는 설치 꾸러미(.deb). AppImage 는 설치 프로그램이
  아니라 굽지도 내놓지도 않고, 옮겨 두었던 것도 지웠다. 서버가 판마다 하나를 골라 준다(`pick`).
- 첫 화면 [시작 체크리스트]는 보이지 않는 것이 기본이다. 여섯 가지를 셀 자료가 다 온 뒤, 접어 두지 않았고 다
  채우지 않은 사람에게만 보인다. [더 이상 표시하지 않기]는 계정(`onboarding_state.checklist_dismissed`)에 남는다.
- 0.8.3 을 태그로 내보내 확인: universal 빌드가 CI 에서 한 번에 됐고, 릴리스 노트는 태그 본문, 다운로드 센터에는
  세 파일이 저절로 올라왔다.
