# 50. 기억 — 무엇을 남기고 무엇을 버리나

## 0. 선은 이미 그어져 있다

```
[내 정보]     = 사용자가 준 것          → 모든 비서가 전부 본다
[비서 메모리] = 상호작용에서 생긴 것    → 그 비서에게 남는다
```

"상호작용" 은 두 갈래다. **주인과의 대화**, 그리고 **밖에서 온 사람과의 대화**.
지금 방 이름(`owner` / `visitors`)이 그 둘이고, 맞다.

이 문서는 그 선을 바꾸지 않는다. **그 선 안쪽이 엉망인 것**을 고친다.

## 1. 지금 무엇이 잘못돼 있나

### 1-1. 심부름이 기억으로 남는다 — 원인 확정

`simulated` 턴은 증류하지 않도록 이미 막아 두었다(`runner.py:677`). 그런데
**심부름을 만드는 두 곳이 `simulated=True` 를 넘기지 않는다.**

```python
# services/blog.py:385  사진 읽기
TurnRequest(owner=owner, agent=agent, conversation=conv, audience="owner", text=asked, attachments=atts)
# services/blog.py:877  글에 댓글 달기
TurnRequest(owner=owner, agent=agent, conversation=conv, audience="owner", text=asked)
```

대화는 `simulated=True` 로 만들었는데 **턴은 아니다.** 그래서 증류가 돌고, 내가
비서에게 시킨 심부름 지시문이 "주인이 한 말" 로 기억된다.

운영에서 나온 것들이 정확히 그 모양이다.

| 남은 기억 | 실제로는 |
|---|---|
| "응답 스타일 지시 — 사진 설명 요청 시: 보이는 것만 객관적으로 간단히…" | 내가 `describe_photos` 에 적은 **지시문 그대로** |
| "장하렴의 글에 댓글 요청 — 글에 댓글을 남겨달라고 요청함" | `secretary_reply` 의 심부름 지시문 |
| "장하렴이 새로운 프로젝트 시작 공지" | 같은 심부름을 한 번 더 |

"사진 읽기" 대화에서 **사실 4건**도 나왔다. 사실 쪽은 `simulated` 가 막고 있어야
하는데 새는 것을 보면, 막는 자리가 한 군데뿐인 것도 문제다.

### 1-2. 노트에 중복 검사가 없다

사실에는 두 겹의 방어가 있다.

- 프롬프트에 **이미 아는 사실 50줄**을 넣어 다시 만들지 말라고 한다.
- 만들어져도 (주체·서술·범위)가 같고 목적어가 같으면 버린다.

**노트에는 둘 다 없다.** `mem.remember` 는 그냥 쓴다. 그래서 운영에
"스완과의 연락 시도" 가 **두 개** 있다.

```
스완과의 연락 시도  (9/13 오후 2:33)  스완에게 인사 메시지를 보내기로 함. 현재 스완의 공개 연락처가…
스완과의 연락 시도  (9/13 오후 1:41)  장하렴이 스완에게 인사 메시지를 보내기를 원함. 스완의 공개 링크/연락처가…
```

같은 일을 52분 간격으로 두 번 적었다. 대화가 이어지는 동안 턴마다 증류가 돌면
**같은 이야기가 턴 수만큼 쌓인다.**

### 1-3. 남길 가치를 판단하는 기준이 모델의 마음뿐이다

지금 규칙은 한 줄이다.

> note: write only if something worth remembering happened (decision, preference, plan, new info).

"worth remembering" 이 무엇인지는 적혀 있지 않다. 그래서 모델은 **턴이 있었다는
사실 자체**를 기억거리로 본다. "댓글을 요청함" 은 요청이 있었다는 기록이지 기억이
아니다. 한 달 뒤에 그 줄을 읽어서 쓸 데가 없다.

### 1-4. 쌓이기만 한다

기억이 늘어나면 검색이 그 안에서 고르므로, 오래되고 쓸모없어진 줄이 새 줄과 같은
자격으로 경쟁한다. 줄이는 길이 없다. 사용자가 손으로 지우는 것뿐이다.

### 1-5. 지식 문서를 한 비서에만 묶는 기능이 남아 있다

`knowledge_documents.agent_id`. 문서를 올릴 때 비서 하나를 고르면 그 비서만 본다.

**철학에 어긋난다.** 지식은 사용자가 준 것이라 [내 정보] 이고, 내 원장은 모든
비서가 전부 본다. 비서 쪽에서 "이 비서는 이것만 안다" 를 정하는 것은 우리가 이미
걷어낸 [지식] 능력 스위치와 같은 종류다.

운영에서 **7개 문서 중 0개, FAQ 0개**가 쓰고 있다. 아무도 안 쓴다.

## 2. 고칠 것

### 고침 1 — 심부름은 턴도 심부름이다

`describe_photos` 와 `secretary_reply` 가 `simulated=True` 를 넘긴다.

그리고 **막는 자리를 하나로 만든다.** 지금은 `runner.py` 의 증류 호출 앞에서만
막는데, 그러면 다른 경로로 증류를 부르는 코드가 생기면 다시 샌다.
`distill_turn` 이 **스스로** 턴을 보고 거절하게 한다.

```python
if turn.simulated:  return {"skipped": "simulated"}
```

턴 행에 그 값이 남아 있어야 하므로 `turns.simulated` 칸을 추가한다.

### 고침 2 — 같은 이야기를 두 번 적지 않는다

두 겹으로 막는다. 사실에 이미 있는 방어와 같은 모양이다.

1. **프롬프트에** 이 대화에서 이미 적어 둔 노트의 제목과 첫 줄을 넣고, 다시 쓰지
   말라고 한다. 사실 쪽 `_already_known` 과 같은 자리다.
2. **쓰기 직전에** 같은 대화에서 나온 최근 노트와 비교한다. 제목이 같거나 본문이
   많이 겹치면 **새로 쓰지 않고 있던 것을 고친다.** 이야기가 진행됐으면 그 줄이
   자라는 것이 맞고, 줄이 하나 더 생기는 것은 맞지 않다.

겹침은 문자로 잰다. 한국어는 조사가 붙어 단어 비교가 잘 안 되므로, **3글자 조각**의
자카드 유사도를 쓴다. `geny` 쪽에서 같은 이유로 쓰던 방식이다.

### 고침 3 — 남길 가치를 말로 적는다

프롬프트에 **무엇이 기억이고 무엇이 아닌지**를 예로 적는다. 규칙을 추상어로 주면
모델은 제 마음대로 읽는다.

기억이 되는 것:
- 주인이 정한 것 ("금요일에 배포하기로 했다")
- 주인이 드러낸 취향·습관 ("긴 설명보다 한 문장을 좋아한다")
- 앞으로 쓸 사정 ("스완의 연락처가 없어 아직 못 보냈다")
- 사람과 관계에 대한 새 정보

기억이 **되지 않는** 것:
- 심부름이 있었다는 기록 ("댓글을 요청함", "사진 설명을 요청함")
- 비서에게 준 지시문 그대로
- 이번 턴에서 답해 버려 끝난 질문
- 비서 자신의 말투·성격

### 고침 4 — 만들지 않는다 (이미 있다)

조사해 보니 **엔진에 이미 있다.** `SynapseConfig` 에 `trust_helpful` ·
`trust_unhelpful` · `trust_half_life_days=45` · `trust_weight=2.0` 가 있고,
비서가 기억을 꺼내 쓰면 `learn()` 이 `trust_feedback` 을 먹인다
(`runner.py:666`). 쓰이지 않은 기억은 45일 반감기로 내려간다.

`learn()` 에 적힌 원칙도 맞다: **"검색에 걸린 것이 쓸모의 증거는 아니다."**
프롬프트에 끼워 넣은 것을 쓸모로 세면 모든 기억이 똑같이 올라간다.

그 위에 또 하나의 최근성 곱셈을 얹으면 엔진과 싸운다. **만들지 않는다.**

### 고침 5 — 지식은 모든 비서가 본다

`knowledge_documents.agent_id` 로 거르는 것을 멈춘다. 칸은 남겨 두되 읽지 않는다
(쓰지 않는 칸을 지우는 것은 되돌릴 수 없고, 운영에 값이 0개다).

올리는 화면에서 비서를 고르는 자리를 빼고, 비서 패널의 [지식] 칸은 **내 지식을
그대로 보여 주는 읽기 전용**으로 바꾼다. "이 비서가 아는 자료" 를 묻는 사람에게
"당신이 올린 전부" 라고 답하는 화면이다.

### 겹침을 무엇으로 재나

처음에 글자 3개 조각(3-gram)으로 쟀는데 **틀렸다.**

```
"금요일에 배포하기로 했다" vs "수요일에 점심을 먹기로 했다"   →  0.300
```

무관한데 높다. 겹치는 것은 "요일에" · "하기로" · " 했다" 뿐인데 짧은 문장에서는
그게 대부분이다. 그래서 **내용어**로 바꿨다. 토큰화기는 엔진 것을 그대로 쓴다
(한국어 조사 떼기가 이미 거기 있고, 여기서 또 만들면 두 벌을 고쳐야 한다).

엔진의 조사 떼기가 **`의` 를 안 뗀다.** 소유격이라 매우 흔해서 그냥 두면 "스완의" 와
"스완" 이 남남이 된다. 엔진을 고치려면 별 패키지를 배포해야 하므로 그 한 글자만
여기서 본다. 떼고 두 글자가 안 되면 떼지 않는다: `회의` · `임의` · `편의` 처럼
`의` 로 끝나는 낱말은 거의 다 두 글자다.

바꾼 뒤 잰 값으로 문턱을 정했다.

```
실제 중복 ("스완과의 연락 시도" 두 개)     0.32 · 0.43
같은 일을 다른 말로 적은 것                0.20
무관한 짧은 문장 (어미만 겹침)             0.17   ← 3-gram 으로는 0.30 이었다
```

**문턱 0.30.** 가운데 0.20 구간은 자동으로 합치지 않는다. 안 합치면 줄이 하나 더
생기고, 잘못 합치면 기억을 잃는다. 되돌릴 수 없는 쪽을 피한다. 그 구간은 프롬프트가
맡는다. 테스트가 이 사실을 못 박아 두었다: 나중에 문턱을 낮추려는 사람이 무엇을
잃는지 보도록.

### 지운 기억 9개

지우기 전에 어느 대화에서 나왔는지 전부 확인했다.

| 방 | 대화 | 기억 |
|---|---|---|
| owner | 사진 읽기 | 응답 스타일 지시 ← **내 코드의 지시문 그대로** |
| owner | 하렴님의 글 | 장하렴이 올린 글에 댓글 요청 |
| owner | 하렴님의 글 | 장하렴이 새로운 프로젝트 시작 공지 |
| owner | 하렴님의 글 | 장하렴의 글에 댓글 요청 |
| visitors | 방문자 시뮬레이션 ×3 | 김진수의 문의, 손성준 문의, 방문객 맞이 |
| visitors | 이 분은 누구셔 ×2 | 김해수 방문, Loan Request |

방문자 쪽 다섯은 **오지 않은 사람에 대한 기억**이었다. 남기면 비서가 김해수가
실제로 방문했다고 믿는다.

## 4. 안 하는 것

- **기억을 [내 정보] 로 옮기지 않는다.** 상호작용에서 생긴 것은 비서의 것이다.
- **기억을 자동으로 지우지 않는다.** 물러나게만 한다 (고침 4).
- **방을 늘리지 않는다.** `owner` 와 `visitors` 가 상호작용의 두 갈래이고 그것으로 충분하다.
