## 1. 마우스를 올렸는데 컨트롤이 안 나온다

### 까닭(추정, 이 환경은 리눅스라 윈도·맥에서 그대로 재현하지는 못했다)

- 0.8.6~0.8.8 은 컨트롤 창을 늘 띄워 두고, 나오고 숨는 것을 **그 페이지 안의 CSS 불투명도**로 했다.
- 크로미움은 가려졌다고 여기는 창의 그리기를 멈춘다(윈도의 가려짐 계산, 뒤로 물러난 창 늦추기). 투명한 창이 겹치거나
  본창이 떠 있지 않은 때 그렇게 여기는 일이 있다 — 그러면 "나왔다" 는 상태는 바뀌어도 그림이 그려지지 않아 아무것도
  보이지 않는다. 사용자가 말한 조건(다른 창이 있음, 본창이 안 뜸)과 맞는다.
- 커서 자리만 보는 알아차림도 하나뿐이었다 — 배율이 다른 둘째 화면에서 커서 자리가 어긋나면 알아차리지 못한다.

### 한 것

- **컨트롤 창 자체를 띄우고 내린다.** 페이지는 늘 보이는 모양으로 그려 둔다. 새로 뜨는 창은 반드시 그려진다.
  (창 불투명도는 윈도의 투명 창과 그리는 방식이 부딪힐 수 있어 쓰지 않는다.) 말풍선이 오르내리지 않게 컨트롤 자리는
  잠겨 있는 동안 늘 비워 둔다.
- **가려짐으로 그리기를 멈추지 않게**: `disable-backgrounding-occluded-windows`, 윈도는
  `disable-features=CalculateNativeWinOcclusion`, 컨트롤 창 `backgroundThrottling: false`.
- **알아차리는 길 셋, 하나만 맞아도**: 운영체제 커서 자리(90ms), 아바타 창이 받은 마우스 움직임(윈도·맥은 통과 창에도
  넘겨준다 — 사진·말풍선·바닥 가운데 컨트롤 자리 위면 `hoverPing`), 컨트롤 창에 마우스가 들어와 있음.

## 2. 화면 보여주기

### 흐름

1. 설정 [화면 → 화면 보여주기] 를 켠다(처음에는 꺼짐 — 화면은 사람이 켜야 나간다). 켜면 단축키 [화면 보여주고 묻기]
   (처음에는 비어 있음)와 트레이 항목이 생긴다.
2. 아바타의 컨트롤·막대, 빠른 대화에 [화면 보여주기](ScanEye).
3. 누르면 **마우스가 있는 화면**을 한 장 찍는다. 찍는 동안 메모라의 창(아바타·컨트롤·빠른 대화)은 잠깐 비킨다.
4. 빠른 대화가 열리고 찍은 화면이 작게 붙는다("지금 화면을 함께 보내요 · 보내기를 눌러야 나가요"). 떼거나 다시 찍을 수 있다.
5. 보내면 그 화면을 올리고(`/api/uploads`) 물음에 붙여 보낸다(`upload_ids`). 글이 없으면 "이 화면 좀 봐 줘." 답은
   아바타의 말풍선으로. 웹의 그 대화에는 화면이 붙은 말로 남는다(실시간으로).

### 구조

- `src/main/capture.ts` — `take()` 한 장 찍기(긴 변 1920, JPEG 82, 작은 미리보기), 맥 화면 기록 권한 확인·안내·설정 열기,
  거의 검은 화면이면 실패로(권한 없이 찍힌 맥 등), 찍는 동안 비키는 손잡이(`setStepAside`). 나중에 "잠깐마다 보기" 같은
  것을 붙일 때도 이 한 장 찍기를 쓴다.
- 찍은 원본은 메인(`controller` 의 `pendingShot`)에만 있고, 빠른 대화에는 미리보기만 간다. 보낼 때 메인이 올린다.
- 윈도는 `AllowWgcScreenCapturer,AllowWgcWindowCapturer` — 옛 캡처는 GPU 로 그리는 창(브라우저·VS Code)을 검게
  찍는다(Geny 와 같음).
- 서버는 바꾸지 않았다: 대화의 첨부와 같은 길(`/api/uploads` → `upload_ids`). 그림을 못 보는 모델이면 서버가 설명을 적는다.
