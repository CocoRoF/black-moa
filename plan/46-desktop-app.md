# 46. 데스크톱 앱 — 비서가 창 하나로 늘 곁에 있다

## 0. 왜

메모라는 지금 브라우저에서만 산다. 브라우저를 닫으면 비서도 없다. 비서가 먼저 말을
걸어도 그 말은 다음에 로그인할 때까지 아무 데도 도착하지 않는다.

비서는 곁에 있어야 하는 것이다. 곁에 있다는 것은 세 가지다.

1. **켜 두면 계속 있다.** 트레이에 남고, 로그인할 때 뜨고, 새 말이 오면 알린다.
2. **말로 할 수 있다.** 타자보다 말이 빠른 순간이 하루에 여러 번 있다.
3. **얼굴이 있다.** 글자만 흐르는 창은 도구이고, 얼굴이 반응하는 창은 상대다.

브라우저는 이 셋 중 어느 것도 제대로 못 한다. 그래서 앱이다.

## 1. 앱은 접속기다

**웹에서 쓰는 것과 앱에서 쓰는 것은 같은 것이어야 한다.** 앱이 존재하는 이유는
기능을 더 주기 위해서가 아니라, 비서를 기기 안에서 더 강하게 쓰기 위해서다.

그래서 **본창은 memo-ora.com 그 자체다.** 로그인도, 비서와의 대화도, 소식도,
커뮤니티도 서버가 주는 그 화면이 한다. 앱은 화면을 다시 만들지 않는다.

앱이 화면을 다시 만들면 반드시 이렇게 된다. 웹에는 있는 사진이 앱에는 없고,
웹에는 있는 마크다운이 앱에는 없고, 웹이 고쳐져도 앱은 안 고쳐진다. 두 벌을
영원히 같이 고치겠다는 약속은 반드시 깨진다.

**앱이 더하는 것은 브라우저가 못 하는 것뿐이다.**

| 더하는 것 | 왜 브라우저로는 안 되나 |
|---|---|
| 아바타 창 (미니 뷰 포함) | 테두리 없는 투명 창, 항상 위, 전체 화면 위에도 |
| 트레이 | 창을 닫아도 남아 있어야 곁에 있는 것이다 |
| 알림 | 브라우저를 닫으면 비서가 부르는 소리가 아무 데도 안 닿는다 |
| 전역 단축키 | 어느 창에서 일하든 비서를 부를 수 있어야 한다 |
| 로그인할 때 시작 | 아침에 켜면 이미 와 있어야 한다 |

## 2. 갱신하는 쪽은 하나여야 한다

여기서 실제로 크게 틀렸다. 처음에는 앱이 제 인증을 따로 들고, 제 갱신 쿠키로
`/api/auth/refresh` 를 불렀다. 본창의 웹도 같은 일을 한다. **같은 갱신 토큰을 두
클라이언트가 나눠 쓴 것이다.**

서버는 갱신 토큰을 한 번 쓰면 돌린다. 이미 쓴 토큰이 다시 오면 20초의 유예
밖에서는 **도난으로 보고 세션 가족 전체를 끊는다.** 운영 `audit_logs` 에
`refresh_reuse_detected` 가 앱을 띄운 시각마다 찍혀 있었다. 증상은 "이유 없이
로그아웃" 하나뿐이라, 쓰는 사람은 앱이 이상하다고만 느낀다.

**갱신하는 쪽은 웹 하나다.** 앱은 묻지 않고 듣기만 한다.

- 본창에 얹는 것은 **한 방향 다리 하나**다(`preload/host.ts`). 내놓는 것은
  `desktop` 표시와 `token(v)` / `signedOut()` 둘뿐이고, **읽어 가는 길은 없다.**
- 웹은 토큰을 얻으면 호스트가 있을 때만 알려 준다. 호스트가 없으면(곧 보통의
  브라우저이면) 아무 일도 일어나지 않는다. 화면이 하는 일은 하나도 달라지지 않는다.
- 앱은 그 토큰을 아바타와 안 읽은 것 세기에 쓴다. 401 이 나면 **기다린다.**
  거기서 갱신하면 그 순간 다시 두 갱신자가 된다.

## 3. 아바타가 말을 거는 길

아바타는 앱이 직접 그리는 유일한 화면이라 턴을 직접 돈다.

- 스트림은 **메인에서 돈다.** 창을 닫아도 답이 안 끊기고, 끊기면 `?after=<seq>` 로
  놓친 데부터 이어 받는다. 서버가 이미 재개를 받아 준다.
- 이벤트 이름은 웹과 같은 것을 쓴다(`text.delta` / `turn.complete` …).
- **말한 것은 웹의 그 대화에 그대로 쌓인다.** 앱에만 남는 대화를 따로 두면
  접속기가 아니다. 아바타에서 물은 것이 웹을 열면 거기 있어야 한다.

## 4. 아바타

메모라에 3D 모델은 없다. 있는 것은 **비서의 얼굴 사진**이다. 없는 것을 억지로
만들기보다 있는 것을 살린다.

아바타 창은 테두리 없는 투명 창이고 항상 위에 뜬다. 그 안에서

- 얼굴이 **숨을 쉰다.** 느린 상하 움직임과 아주 약한 확대·축소.
- 말할 때 **소리에 반응한다.** TTS 로 받은 음성을 WebAudio 로 분석해 그 크기만큼
  얼굴 둘레의 고리가 살아나고 고개가 미세하게 흔들린다.
- 답은 **말풍선에 한 글자씩** 찬다. 스트리밍 그대로다.
- **말로 물을 수 있다.** 마이크 버튼을 누르고 말하면 `POST /agents/{id}/stt` 로 글이
  되고, 답은 `POST /agents/{id}/tts` 로 소리가 된다. 두 엔드포인트 모두 이미 있다.

입모양을 흉내 내지 않는다. 평면 사진으로 하는 입모양은 반드시 어색하고, 어색한
흉내는 없느니만 못하다. 대신 **숨·시선·소리·고개** 네 가지로 살아 있게 한다.

## 5. 곁에 있다는 것

- **트레이.** 창을 닫아도 앱은 남는다. 트레이에서 바로 열고, 바로 말을 건다.
- **알림.** 30초마다 안 읽은 방과 인박스를 확인해 새것만 알린다. 누르면 그 자리로 간다.
- **빠른 말 걸기.** 전역 단축키 하나로 어디서든 작은 입력창이 뜬다.
- **로그인할 때 시작.** 윈도·맥은 로그인 항목, 리눅스는 `~/.config/autostart`.
- **한 번에 하나.** 자료 폴더당 한 벌만 돈다. 두 번째로 켜면 있던 창이 올라온다.

## 6. 만드는 법과 내보내는 법

`desktop/` 한 폴더에 선다. electron-vite 로 main·preload·renderer 를 굽고,
electron-builder 로 세 운영체제 설치본을 만든다.

- 윈도 `Memora_windows_<버전>.exe` (NSIS, 설치 위치 고를 수 있음)
- 맥 `Memora_macos_<arch>_<버전>.dmg` (arm64 · x64)
- 리눅스 `Memora_linux_<버전>.AppImage` · `.deb`

`v*` 태그를 밀면 GitHub Actions 가 세 러너에서 동시에 굽고 한 릴리스에 붙인다.
릴리스는 **먼저 하나 만들어 두고** 각 러너가 거기에 올린다. 러너마다 릴리스를
만들게 두면 진 쪽이 422 로 죽는다(geny-app 에서 겪은 것).

## 7. 안 하는 것

- **서버를 고치지 않는다.** 앱 때문에 API 가 한 줄도 바뀌지 않는다.
- **웹 화면을 베끼지 않는다.** 소식과 커뮤니티는 서버가 주는 그 화면이다.
- **입모양을 흉내 내지 않는다.** (§4)
- **자동 업데이트를 약속하지 않는다.** 저장소가 비공개라 설치본이 토큰 없이는
  안 내려온다. 업데이트 확인은 조용히 실패하고, 앱은 릴리스 페이지를 열어 준다.

## 8. 실행 기록 (2026-09-21, 만들고 확인 완료)

`desktop/` 한 폴더에 섰다. 메인·preload·렌더러 + 계약 하나. 실서버(memo-ora.com)에
실제 계정으로 붙여 확인했다.

**겪은 것.**

- **ESM 메인 진입점.** Electron 43.7 은 ESM 메인을 `.mjs` 로만 받는다. `type: module`
  로 두면 `out/main/index.js` 가 ESM 인데 확장자가 `.js` 라, `electron` 에서 이름 있는
  내보내기를 못 찾고 죽는다. 확장자를 맞추려 빌드를 비트는 대신 메인·preload 를
  **CJS 하나로** 두었다. 렌더러는 어차피 번들러가 굽는다.
- **`ELECTRON_RUN_AS_NODE`.** 이 작업 환경에 켜져 있었다. 그대로 물려주면 Electron 이
  순수 Node 로 돌아 창이 하나도 안 뜨는데, 오류는 "Process failed to launch" 한 줄이라
  앱 문제로 보인다. 앱 문제가 아니었다.
- **말풍선이 비어 있었다.** 서버가 쓰는 칸 이름은 `content` 인데 `text` 로 읽고
  있었다. 화면은 멀쩡히 뜨고 글자만 없어서, 타입 검사도 테스트도 못 잡는다.
  계약에서 서버 이름을 그대로 쓰기로 했다.
- **얼굴 사진이 다 깨졌다.** 서버가 주는 주소는 `/presets/...` 처럼 앞이 잘려 있다.
  브라우저에서는 그게 곧 memo-ora.com 이지만 앱의 창은 `file://` 위에 서 있다.
  앞을 붙이는 함수 하나를 두고 모든 얼굴이 그걸 지나게 했다.
- **버튼 줄이 사이드바 밖으로 64px 나갔다.** 버튼에 `shrink-0` 을 붙인 탓에 `w-full`
  버튼이 제 칸보다 작아지지 못했다. 삐져나온 버튼이 대화 영역을 덮어 눌리지 않았다.
  자리를 grid 로 못 박고, **삐져나온 것이 있으면 실패하는 검사**를 넣었다.
- **`.deb` 은 관리자 이메일을 요구한다.** 이름만으로는 안 만들어진다. `desktopName`
  이 없으면 실행 중인 창이 `.desktop` 항목과 안 이어져 독에 기본 아이콘이 뜬다.

**확인한 것.** 빈 프로필이면 로그인 화면이 뜨고, 실제 계정으로 로그인하면 비서와
지난 대화 37개가 글자와 얼굴을 갖고 서고, 소식·커뮤니티·인박스·인맥·비서 홈 다섯
자리가 각자의 주소로 뜨면서 **어느 것도 로그인 화면으로 튕기지 않고**(세션 공유가
된다는 뜻), 아바타 창이 비서 얼굴로 뜨고, 껐다 켜면 다시 로그인하지 않는다.
구워 낸 AppImage 를 직접 띄워 preload 다리까지 붙는 것을 봤다. 오류 0건.

## 9. 실행 기록 (2026-09-22, 접속기로 되돌림)

처음 만든 것은 접속기가 아니었다. 로그인 화면과 비서 채팅을 앱이 따로 그렸고,
그 채팅에는 웹에 있는 사진도 마크다운도 도구 카드도 없었다. **웹보다 못한 다른
앱을 하나 더 만든 것이다.** 전부 지웠다.

- 지운 것: 네이티브 로그인, 네이티브 채팅, 앱의 왼쪽 줄, 웹 화면을 앱 안에
  끼워 넣던 `WebContentsView` 묶음. 본창은 이제 `memo-ora.com/app` 을 그대로 연다.
- 서버 로그에서 앱 트래픽을 알아보려고 붙였던 `X-Memora-Client` 헤더도 뺐다.
  서버 입장에서도 같은 것이어야 한다.
- **가장 큰 것은 §2 의 갱신 충돌이다.** 앱을 띄울 때마다 세션이 끊길 수 있었다.
  고친 뒤 90초를 켜 두고도 로그아웃되지 않았고, 운영의 `refresh_reuse_detected`
  건수는 76에서 **하나도 늘지 않았다**(고치기 전에는 실행할 때마다 늘었다).

**아바타.** 펼친 모양(300×430)과 접은 미니 뷰(132×172) 둘이다. 접을 때 오른쪽 아래
모서리를 붙잡아 둔다. 왼쪽 위를 기준으로 줄이면 접을 때마다 창이 화면 한가운데로
걸어 들어온다. 접힌 얼굴을 누르면 바로 듣기 시작한다.
`--avatar` 로 켜면 로그인된 뒤에 아바타가 저절로 뜬다.

**확인한 것.** 본창이 `memo-ora.com` 이고, 앱 전용 화면이 끼어들지 않고, 본창에
얹힌 다리는 `desktop` / `token` / `signedOut` 셋뿐이며 읽어 가는 길이 없다.
웹 로그인 화면으로 로그인되고, 소식의 사진 9장이 하나도 안 깨지고, 90초를 켜
두어도 로그아웃되지 않는다. 아바타가 뜨고, 접히고, 제자리에 있고, 다시 펴지고,
"안녕하세요, 하렴 사장님!" 을 받아 말풍선에 띄웠다. 오류 0건.

## 10. CI 가 이 규칙들을 지킨다

접속기라는 약속은 사람이 기억해서 지켜지지 않는다. 다음에 누군가(나를 포함해)
"앱에 이 화면 하나만 네이티브로" 라고 생각하는 순간 다시 갈라진다. 그래서
`ci.yml` 의 `desktop` 잡이 매 푸시마다 본다.

1. 본창이 `memo-ora.com/app` 을 여는가
2. 서버 주소가 고정인가
3. `src/main/` 어디에도 `auth/refresh` 가 없는가 (§2)

셋 다 일부러 어겨서 실패하는 것을 확인했다. 계약 테스트도 넷 늘렸다. 본창에 얹은
다리에 읽어 가는 함수가 생기면 실패하고(내놓는 것은 `desktop`·`token`·`signedOut`
셋뿐이어야 한다), 접은 아바타가 오른쪽 아래 모서리를 놓치면 실패한다.

**릴리스에서 겪은 것 둘.**

- `electron-builder` 에게 올리기를 맡기면 태그를 `package.json` 의 버전에서
  `v<버전>` 으로 **지어낸다.** `desktop-v0.6.0` 을 밀었는데 `v0.6.0` 이라는 릴리스를
  새로 만들어 거기 올렸다. 굽기만 시키고, 어디에 올릴지는 `publish` 가 태그로 못 박는다.
- 맨 위 `defaults.run.working-directory: desktop` 이 **모든 잡의 `run` 에** 걸린다.
  내려받은 설치본은 작업 공간 뿌리에 있는데 `desktop/` 안에서 찾다가 죽었다.
  세 운영체제가 다 성공한 뒤 마지막 한 줄에서 죽는 것이라 제일 아깝다.
- 맥 러너가 Electron 을 받다가 504 로 두 번 죽었다. 코드 문제가 아니라
  일시적인 것이고, 다시 돌리니 통과했다.
