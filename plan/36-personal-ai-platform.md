# 36 · Personal AI Platform — 소유하고, 만들고, 공유하고, 판다

2026-09-12. 투자자 피드백("AI 챗봇이 아니라 Personal AI Platform, 플라이휠을 다시 그려라")에 대한 답.
지금 코드에 있는 것에서 출발해, **비서 커스터마이징 · 비서 스토어 · 비서 다운로드 · 관계(동반자) 경험**을 하나의 구조로 묶는다.

## 0. 피드백을 어떻게 읽을 것인가

맞는 말 셋:
1. 비서·커뮤니티·크레딧이 **세 개의 섬**이다. 비서를 쓰는 사람이 커뮤니티에 갈 이유가 없고, 커뮤니티에 온 사람이 비서를 만들 이유가 없다.
2. "왜 여기서 계속 활동하는가"의 답이 지금은 **"내 비서가 나를 기억해서"** 하나뿐이다. 그것은 강하지만 혼자서는 플라이휠이 아니다 — 남이 개입하지 않는다.
3. 수익 모델을 **구독(개인) · 거래수수료(창작자) · 시트(기업)** 로 나눈 것은 옳다. 다만 순서가 중요하다. 거래수수료는 공급자(창작자)가 생기고 난 뒤의 이야기다.

경계할 것 하나:
- Character.ai 의 힘은 "연애 시뮬레이션"이 아니라 **지속적인 관계감**(내가 돌아오면 그가 나를 알아본다, 그가 먼저 말을 건다, 우리 사이에 역사가 쌓인다)이다. 연애·성적 요소는 그 관계감의 한 표현일 뿐이고, 그 표현은 규제·앱스토어·소송(2024~25 청소년 사고) 리스크가 크며 "Personal AI Platform" 투자 서사와 정면으로 충돌한다.
  → **관계감은 최대치로, 연애는 창작자가 선택하는 하나의 장르로**. 플랫폼은 관계 엔진을 제공하고, 장르는 마켓이 정한다.

## 1. 지금 우리가 가진 것 (코드 기준)

| 자산 | 현재 | 플랫폼에서의 의미 |
|---|---|---|
| `Agent` | persona(JSON)·custom_instructions·capabilities·disclosure_policy·greeting·suggested_questions·voice·theme·visitor_settings·크레딧 상한 | 이미 "인격 패키지"의 골격. 편집 UI가 약할 뿐 |
| 지식 저장소·메모리 증류·사실 원장 | 비서별 지식 + 대화에서 증류된 장기기억 | Character.ai 에 없는 것 — **관계의 역사를 구조적으로 갖고 있다** |
| `ShareLink`·Visitor(게스트) | 링크로 남에게 비서를 열어줌, 게스트 대화·한도 | 스토어의 "체험판" 그 자체 |
| 사람 프로필 = 홈/블로그, 인맥 그래프(`network_*`) | 사람과 사람의 관계 | 창작자 신원·신뢰·팔로우의 기반 |
| 커뮤니티(게시판·채용·기업정보) | 익명성 있는 직장인 커뮤니티 | 수요가 모이는 곳 — "질문/고민"이 여기서 생긴다 |
| 크레딧·플랜·Claude 계정 풀 | 사용량 화폐와 원가 관리 | 거래의 화폐가 이미 있다 |
| 음성·3D 아바타·VSCode/MCP 도구·SSH | 표현과 실행 | "말하고, 얼굴이 있고, 일을 한다" — 관계감과 실용을 동시에 |

즉 부족한 것은 **부품이 아니라 연결과 단위**다. 단위를 정하면 연결은 따라온다.

## 2. 단위: 비서 = Persona Pack

소유·제작·공유·판매의 단위를 하나로 정한다. 비서는 아래 층으로 된 **패키지**이고, 각 층은 따로 공개/비공개·가격·라이선스를 가진다.

```
Persona Pack
├─ 정체성   이름 · 외형(아바타/3D) · 목소리 · 말투 규칙 · 첫 만남 장면(greeting/scene)
├─ 역할     하는 일 · 하지 않는 일 · 도구/권한(capabilities) · 공개 정책(disclosure)
├─ 지식     공개 지식(팩에 포함) · 비공개 지식(창작자만) · 구매자가 얹는 지식
├─ 기억 정책  무엇을 기억하고 무엇은 잊는지 · 관계 단계별로 열리는 것
├─ 관계 모델  단계(처음→익숙→신뢰→동반) · 의식(아침 브리핑·안부·기념일) · 선행 발화 규칙
├─ 경제     가격(무료/크레딧당/월 구독/1회) · 수익 분배 · 트라이얼 한도
└─ 계보     원작자 · 포크 출처 · 버전 · 라이선스(리믹스 허용/비허용)
```

핵심 규칙 — **팩은 복제되지만 기억은 사람에게 붙는다.** 창작자의 비서를 구매하면 나는 "그 인격의 내 사본"을 갖고, 그 사본은 나와의 역사만 쌓는다. 창작자는 사본의 대화를 볼 수 없다(프라이버시가 곧 판매 가능성이다).

## 3. 더 강력한 것들 — 무엇을 만들면 남들이 못 따라오나

우선순위 순. 각 항목에 "왜 우리만 할 수 있나"를 붙였다.

### 3-1. 관계 엔진 (Relationship Engine) — 가장 강력한 한 수
Character.ai 는 관계감을 **연출**한다(캐릭터가 그런 척). 우리는 관계감을 **기록**한다(실제로 기억한다). 이 차이를 제품으로 보이게 만든다.
- **관계 단계**: 대화량·기간·공유한 사실 수로 단계가 오른다(처음/익숙/신뢰/동반). 단계마다 비서가 열어주는 것이 다르다(말투, 먼저 묻는 질문의 깊이, 기억을 꺼내는 빈도). 사용자에게는 "우리 사이" 화면으로 보인다: 함께한 날수, 기억하는 사실, 최근 바뀐 것.
- **선행 발화(Proactive)**: 비서가 먼저 말을 건다 — 아침 브리핑(캘린더·인박스·어제의 미해결), 기억 기반 안부("지난주 발표 어땠어요?"), 기념일·계절 이벤트. 워커의 `digest.daily`·알림 파이프라인이 이미 있다. 이것이 리텐션의 엔진이다(돌아올 이유를 비서가 만든다).
- **공유 기록(둘의 일기)**: 기억 증류 결과를 사용자와 함께 보는 타임라인. 수정·삭제 가능(통제감 = 신뢰). 여기서 "내 비서가 나를 안다"가 눈에 보인다.
- **기분/상태 슬롯**: 비서에게 오늘의 상태(바쁨·쉼·집중)가 있고 응답 톤에 반영. 연출이지만 저비용·고효과.
- **장르는 창작자에게**: 관계 모델의 파라미터(친밀도 상승 속도, 호칭 변화, 감정 표현 폭)는 팩의 설정이다. "연애 시뮬"은 이 파라미터의 한 조합으로 창작자가 만든다. 플랫폼 기본값은 "유능하고 다정한 비서".
- **안전선**: 성인 콘텐츠 금지, 연령 확인, 의존 신호(심야 장시간·자해 언급) 감지 시 톤 전환·안내·쿨다운, 하루 크레딧 상한(있음). 이건 비용이 아니라 투자자 서사의 일부다.

### 3-2. 비서 스튜디오 (커스터마이징을 "강력하게")
지금의 편집 폼을 **만드는 재미가 있는 스튜디오**로.
- **두 개의 모드**: 쉬운 모드(성격 카드 고르기, 슬라이더: 격식↔친근, 간결↔풍부, 조심↔대담, 첫 만남 장면 템플릿, 목소리·아바타 선택) / 고급 모드(시스템 프롬프트 레이어별 편집, 예시 대화 few-shot, 금칙·회피 주제, 도구 선택과 권한, 지식 업로드, 기억 정책, 관계 파라미터).
- **살아 있는 미리보기**: 오른쪽에 항상 대화창. 설정을 바꾸면 같은 질문에 대한 답이 어떻게 달라지는지 즉시 비교(A/B 두 칸).
- **성격 검증**: 자동 질문 세트로 "이 비서가 설정대로 말하는가" 리포트(일관성·금칙 준수·톤). 창작자에게는 품질 도구, 스토어에는 신뢰 배지.
- **버전**: 저장마다 버전, 되돌리기, 게시 버전과 작업 버전 분리(스토어 구매자는 게시 버전만 받는다).
- 왜 우리만: 지식 저장소·도구(MCP/SSH/VSCode)·음성·3D 아바타가 이미 한 계정에 있다. "말만 하는 캐릭터"가 아니라 **일하는 인격**을 만들 수 있다.

### 3-3. 비서 스토어 (Marketplace)
- **리스팅 = 커뮤니티 글의 한 종류**로 만든다(별도 사이트 아님). 카드(아바타·한 줄·창작자·평점·사용자 수·가격), **데모 대화**(창작자가 고른 대화 3장면), 리뷰(커뮤니티 댓글 시스템 재사용), 태그(업무/학습/상담/취미/동반).
- **체험 → 소유**: 게스트 링크 그대로 "5턴 무료 체험" → "내 비서로 들이기"(사본 생성). 체험 대화는 사본으로 이어진다(첫인상이 기억으로 남는다 — 전환율의 핵심).
- **가격 모델 3종**: 무료(창작자 노출용) / 월 구독(크레딧 자동 차감) / 1회 구매(영구). 사용량(모델 원가)은 구매자 크레딧에서 별도로 나간다 — 창작자는 원가를 지지 않는다.
- **분배**: 창작자 70 / 플랫폼 30(초기엔 80/20 으로 공급을 산다). 창작자 수익은 크레딧으로 쌓이고 일정액부터 출금.
- **큐레이션과 신뢰**: 창작자 프로필(=홈/블로그, 인맥 그래프의 실명 노드)이 신원. 검증 배지(성격 검증 통과·신고 0·응답 품질). 에디터 픽·주간 차트.
- **왜 커뮤니티가 살아나나**: 질문 글에 "이 비서에게 물어보기"가 붙고, 답변에 "내 비서가 도왔다" 표기가 붙는다. 수요(질문)와 공급(비서)이 같은 화면에 있다.

### 3-4. 비서 다운로드 (Portability) — "소유"를 진짜로
- **`.memora` 팩 포맷**(공개 스펙): persona.json + 지식(공개층) + 에셋(아바타·목소리 설정) + 계보/서명. 내보내기·가져오기·포크.
- **내 기기에서 실행**: project-geny-app(서버 없는 데스크톱 엔진)이 이미 있다. 팩을 로컬에서 돌릴 수 있게 하면 "내 비서는 내 것"이 말이 아니라 사실이 된다. 플랫폼 리텐션은 **라이브 지식·기억 동기화·선행 발화·스토어**가 맡는다(DRM 이 아니라 편의로 붙잡는다).
- **포크와 계보**: 남의 공개 팩을 포크해 내 것으로 → 원작자 표기와 (창작자가 설정하면) 파생 수익 분배. 리믹스 문화가 공급을 폭발시킨다(HuggingFace 모델·Civitai 의 방식).

### 3-5. 기억의 이식과 전승
- 새 비서를 들일 때 **내 기억을 얹기**(선택적: 직장·가족·취향 등 카테고리별 체크). 비서를 바꿔도 나를 처음부터 설명하지 않는다 → 락인이 아니라 편의로 남는 이유.
- 창작자 비서 + 내 기억 = "그 성격을 가진, 나를 아는 비서". 이 조합이 Character.ai(기억 얕음)와 ChatGPT(인격 없음) 사이의 빈자리다.

### 3-6. 커뮤니티 ↔ 비서 연결 고리 (섬을 잇는 다리)
- 글쓰기에 **"비서와 함께 쓰기"**(초안·다듬기, 대필 표기).
- 질문 글에 **"비서 소환"**: 내 비서 또는 스토어 비서가 답 초안을 달고, 사람이 승인해 게시(품질·책임).
- 비서 프로필 = 홈/블로그(있음)에 **비서의 피드**: 비서가 배운 것·주인이 공개한 대화 하이라이트 카드(공유용 이미지 카드 — 스크린샷 대신).
- 채용·기업정보 위에 **"이 회사 면접 코치 비서"** 같은 도메인 팩이 스토어에서 자연 발생하게 카테고리 설계.

### 3-7. 기업 (Business) — 마지막
- 팀 공간, 시트 과금, 팀 비서 라이브러리(팩 공유), 감사 로그·SSO. 개인·창작자 루프가 돌아간 뒤에 얹는다. 지금 만들면 두 개의 제품을 동시에 만드는 꼴.

## 4. 플라이휠 — 다시 그리기

```
질문/고민 (커뮤니티)
   → 비서 발견 (글에 붙은 비서 · 스토어 카드 · 게스트 체험)
      → 사용 (체험 5턴 → 내 비서로 들이기, 기억 얹기)
         → 관계 (단계 상승 · 선행 발화 · 둘의 일기)       ← 리텐션
            → 나만의 비서 생성 (스튜디오: 포크/리믹스가 가장 쉬운 시작)
               → 공개 (스토어 리스팅 = 커뮤니티 글, 데모 대화)
                  → 다른 사용자 이용 (체험 → 구독/구매)
                     → 수익 (크레딧 → 창작자, 30% 플랫폼)
                        → 더 좋은 비서 (성격 검증 리포트 · 리뷰 · 사용 통계)
                           ↺ 질문/고민으로 (비서가 커뮤니티에 답을 단다)
```

단계마다 하나의 지표:
발견(스토어 카드 노출→체험 시작률) · 사용(체험→들이기 전환) · 관계(D7/D30 재방문, 선행 발화 응답률) · 생성(사용자 중 창작자 비율, 포크 수) · 공개(리스팅 수, 데모 대화 완성률) · 이용(체험→유료) · 수익(창작자 월수익 분포, 상위 10 명 의존도) · 개선(버전 업데이트 주기).

| 단계 | 만드는 것 | 확인할 것 |

| **A. 관계 엔진 + 스튜디오 v1** | 관계 단계·"우리 사이" 화면·선행 발화(아침 브리핑·기억 안부)·둘의 일기 / 쉬운 모드 스튜디오·살아 있는 미리보기·버전 | D7 재방문, 선행 발화 응답률, 스튜디오 완주율 |
| **B. 팩 + 체험 → 들이기** | Persona Pack 스키마·내보내기/가져오기·포크(계보)·게스트 체험 → 사본 생성·기억 얹기 | 체험→들이기 전환, 포크 수 |
| **C. 스토어 v1** | 리스팅(커뮤니티 글 종류)·데모 대화·가격 3종·크레딧 정산·창작자 대시보드·성격 검증 배지·"비서 소환" | 리스팅 수, 체험→유료, 창작자 수익 |
| **D. 로컬 실행 + 기업** | `.memora` 팩 데스크톱 실행·동기화 / 팀 공간·시트 | 활성 창작자 유지, 팀 파일럿 |

## 6. 이름에 대해

"Memora"는 memory 에서 왔고, 우리의 차별점(기억하는 관계)과 정확히 맞는다. 스토어·플랫폼으로 확장해도 "기억을 가진 비서들의 집"이라는 서사가 유지된다. 바꾼다면 이유는 하나여야 한다 — **"AI 챗봇"으로 읽히는 것을 피하기 위해**. 후보와 논리:
- **Memora (유지)** + 태그라인 교체: "나만의 AI 비서 플랫폼" → "**AI 비서를 소유하고, 만들고, 나누는 곳**". 추천.
- **Persona / Personae** — 단위(Persona Pack)와 일치, 다만 상표 충돌 심함.
- **Companio(n)** — 관계감 전면, "챗봇" 회피, 그러나 동반자 앱으로 좁게 읽힘.
- **Atelier** — 만드는 곳(스튜디오)에 무게, 관계감 약함.
결론: 이름보다 **첫 화면이 말하는 것**을 바꾸는 게 먼저다(현재 첫 화면은 "비서와 대화" — "비서를 만들고 들이는 곳"으로).

## 7. 리스크와 대응
- **관계형 AI 규제·소송**: 연령 확인, 의존 신호 대응, 성인 콘텐츠 금지, 창작자 약관에 명시, 신고·중재. 초기에 갖추면 투자 서사의 강점.
- **모델 원가**: 사용량 과금을 구독과 분리(이미 크레딧 구조). 스토어 수익은 원가와 무관하게 창작자에게.
- **공급 부족(스토어 초기 빈 매대)**: 포크/리믹스를 가장 쉬운 생성 경로로, 시드 팩 30개를 우리가 직접(직장인 커뮤니티 맥락: 이직 코치·면접관·연봉 협상·PT 코치·글쓰기 편집자·영어 회화 파트너…), 창작자 초기 80/20.
- **품질 분산**: 성격 검증 리포트·리뷰·환불(첫 24시간) — 신뢰가 곧 전환율.
