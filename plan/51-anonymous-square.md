# 51. 광장은 익명, 내 집은 실명

## 0. 두 집을 다시 나눈다

plan/41 이 그은 선을 그대로 쓰되, 흐릿하던 곳을 못 박는다.

| | **피드** (내 집) | **커뮤니티** (광장) |
|---|---|---|
| 이름 | **실명.** 인스타그램처럼 | **익명.** 늘 광장 이름 |
| 비서 | **본다.** 내 글은 내 비서의 재료다 | **보지 않는다.** 길 자체가 없다 |
| 원장 | [내 정보] 에 센다 | 세지 않는다 — 나로서 나가지 않으므로 |

## 1. 무엇이 틀려 있었나

### 1-1. 광장에 실명으로 쓰는 길이 있었다

글을 쓸 때 [실명으로 쓰기] 가 **기본으로 켜져** 있었다. 비우면 계정 이름이 그대로
걸렸다. 운영 11편 중 **8편이 실명**이었다.

plan/41 은 이미 "광장 = 익명 또는 필명" 이라고 적어 두었다. 화면이 그 말과 달랐다.

### 1-2. 댓글이 더 크게 샜다

글쓴이만 제 필명을 지켰고, **댓글을 다는 사람은 실명으로 나왔다.**

```python
# 예전 api/community.py
if pen and shown is not None and post_author_id is not None and c.author_id == post_author_id:
    shown = {... 필명 ...}      # 글쓴이만
```

남의 익명 글에 한 줄 다는 것만으로 내 실명이 광장에 걸렸다. 익명 게시판에서 이건
가장 큰 구멍이다: 글은 숨기고 댓글로 드러나는 것이라, 숨긴 줄 알고 쓰게 된다.

### 1-3. 비서가 광장 글을 알고 있었다

실명으로 쓴 글만 비서의 재료로 들였다(`community.sync_knowledge`). 필명 글은
막았으니 경계를 지킨 것처럼 보였지만, **익명이라는 말과 어긋난다.** 익명은 "그 글이
나와 이어지지 않는다" 는 뜻이고, 내 비서가 그 글을 알고 있으면 언젠가 어떤 말끝에서
두 이름이 만난다.

## 2. 고친 것

### 광장 이름은 비어 있을 수 없다

```python
def pen_for(user_id, given):
    return _clean_pen_name(given) or pen_name_for(user_id)
```

안 고르면 지어 준다. **같은 사람은 늘 같은 이름이다** — 계정 id 의 해시에서 뽑는다.
글마다 이름이 달라지면 대화가 이어지지 않고 답글이 누구에게 하는 말인지 알 수 없다.
그 이름에서 계정으로 거꾸로 갈 길은 없다.

화면에서 [실명으로 쓰기] 를 없앴다. 이름 칸은 남기되 비워 두어도 된다.

### 참여자 전원이 익명이다

글쓴이는 그 글에 적힌 이름을 그대로 쓰고(제 글 아래에서 이름이 바뀌면 남처럼 보인다),
나머지는 각자의 광장 이름을 쓴다. 계정 id 는 아무에게도 나가지 않는다.

`is_me` 는 남긴다. 내 댓글을 고치고 지우는 것은 내 일이고, 그 값은 **나 자신에게만**
참이라 남에게 무엇도 알려 주지 않는다.

### 비서로 가는 다리를 없앴다

`community.sync_knowledge` 를 지웠다. 설정으로 막는 것이 아니라 **길을 내지 않는다.**
내 글이 비서에게 가는 길은 [피드] 하나다.

### 원장에서 광장을 뺐다

[내 정보] 의 요약은 "내 무엇이 **나로서** 밖에 나가나" 다. 익명 글은 나로서 나가지
않는다. 세어 두면 그 줄이 거짓말이 된다.

## 3. 이미 쌓인 것

이관(0065)은 **이름을 가리는 쪽으로만** 간다.

- 필명이 없는 글에 그 사람의 광장 이름을 붙인다. 같은 사람은 늘 같은 이름이라
  지난 글들의 대화가 끊기지 않는다.
- 광장에서 온 지식 문서와 그 조각을 지운다.
- **되돌리지 않는다.** 익명이던 것을 실명으로 되돌리는 것은 되돌릴 수 없다.

## 4. 배포에서 겪은 것

이관이 운영에서 두 번 멈췄고, 그동안 **백엔드가 재시작을 반복했다.**

1. `exec_driver_sql` 에 `%s` 자리표시자를 썼다. asyncpg 는 그것을 모른다
   (`syntax error at or near "%"`).
2. `sa.text` 로 바꾸니 이번에는 `jsonb_build_object` 안의 인자 타입을 정하지 못했다
   (`could not determine data type of parameter $1`). `CAST(:pen AS text)` 로 못 박았다.

**배운 것.** 테스트 DB 에는 그 조건에 걸리는 행이 없어서 반복문이 돌지 않았고,
테스트가 통과해도 이관이 도는지는 알 수 없었다. 두 번째 고친 뒤에는 **운영의 asyncpg
로 그 문장을 먼저 돌려 보고**(`AND false` 를 붙여 아무것도 안 바꾸게) 배포했다.

프론트에서도 하나. `npm run lint` 는 통과하는데 `npm run build` 가 더 엄격해서
쓰이지 않는 들여오기 하나로 배포가 깨졌다. **배포 전 기준은 빌드다.**

## 5. 확인한 것 (2026-09-22, 실서버)

| 본 것 | 결과 |
|---|---|
| 이관(0065) | 실명 8편이 광장 이름으로 가려짐 |
| 같은 사람 = 같은 이름 | "월요일싫은 기획자" 3편, "야근중인 개발자" 2편 |
| 목록에서 계정 id | **0개** |
| 광장에서 온 지식 문서 | **0개** |
| 글쓰기 화면 | [실명으로 쓰기] 사라짐, "광장은 익명이에요" |
| 원장 | 4줄(프로필·내 블로그·지식·인맥), 커뮤니티 없음 |

"장하렴" 이라고 적힌 글이 하나 남아 있다. 그건 그 사람이 **필명 칸에 직접 적은 것**
이다. 스스로 드러내는 것은 본인의 선택이고, 우리가 막을 일이 아니다. 막아야 하는
것은 **고르지 않았는데 드러나는 것**이고, 그건 없앴다.

테스트도 못 박았다. 광장 글은 어떤 경우에도 비서에게 가지 않고(함수도 부르는 자리도
없다), 이름을 안 골라도 필명이 붙고, 댓글은 글쓴이도 남도 익명이다.

## 덧: 광장으로 난 다른 길 둘 (2026-09-22)

"길을 내지 않는다" 고 적은 뒤에도 두 길이 남아 있었다. 둘 다 **고친 자리만 다른
같은 구멍**이다.

### 알림이 실명을 들고 나갔다

`_notify` 의 `actor_name` 이 `nickname or display_name` 이었다. 글과 댓글에서
실명을 걷어내고도 내 글에 달린 댓글 알림이 그 사람의 계정 이름을 말했다. 운영에
그렇게 쌓인 것이 일곱 건이다. 0067 이 이미 쌓인 것까지 광장 이름으로 덮었다.

**익명은 표면 하나가 아니라 그 사람이 나가는 모든 출구에서 지켜야 한다.** 세어 볼
곳은 화면·인박스·실시간 토스트·메일이었다.

### 비서가 인박스로 광장을 보고 있었다

지식 문서로 가는 다리는 지웠는데 `inbox_list`·`inbox_read` 는 광장 알림까지
돌려주고 있었다. 제목 하나면 "내 주인이 광장에 그 글을 썼다" 가 비서의 아는 것이
되고, 그 앎이 언젠가 방문자 앞에서 두 이름을 잇는다.

막는 자리는 **서비스 하나**다(`list_items(secretary=True)`, `get_owned(secretary=True)`).
도구에서 걸렀으면 다음 도구가 생기는 순간 다시 샌다. 목록에서 가리는 것만으로는
모자라서 id 로 읽는 길도 같이 닫았다.
