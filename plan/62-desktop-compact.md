# plan/62 — PC 앱: 쓰기 위한 앱

## 0. 요청 (2026-09-28)

지금 PC 앱은 웹을 창에 옮겨 놓은 것뿐이다. XGen Dex 처럼 아이콘 사이드바(VS Code)로 가고, [소식]·[커뮤니티]·
[비서와 대화] 세 개가 기본이 되는 강력한 틀로, 다른 기능은 너무 많이 가져가지 않는다. xgen-dex·Geny 처럼
비서를 띄워 두는 작은 아바타 창과 강력한 빠른 대화를 제대로. 메모라의 디자인은 쓰되, 컴팩트하게 — 말 그대로
"사용을 위한 앱".

## 1. 무엇이 문제였나

- 본창 = memo-ora.com/app 그대로(plan/46 §1). 웹 사이드바의 열몇 개 자리(비서 홈·비서 관리·대화 기록·정보·
  스케줄·메일·피드·지식·파일·인맥·인증·연동·크레딧·알림·계정 설정·관리자)가 그대로 들어와 "웹의 복사본" 이었다.
- plan/46 §9 의 교훈은 그대로 유효하다: 앱이 채팅을 따로 그렸더니 사진·마크다운·도구 카드가 빠진 **웹보다
  못한 앱**이 되었다. 화면을 두 벌 만들면 반드시 갈라진다.

## 2. 원칙

1. **세 개의 문**: 비서와 대화 · 소식 · 커뮤니티. 앱의 틀(아이콘 막대)에는 이 셋만 선다.
2. **비서가 곁에**: 작은 아바타 창과 빠른 대화 창은 앱만의 것이다(브라우저가 못 한다).
3. **안쪽은 여전히 한 벌**: 틀(아이콘 막대·제목 줄·설정·알림·아바타·빠른 대화)은 앱이 그리고, 세 문의 **안쪽은
   웹이 "앱 모드" 로** 그린다. 사진·마크다운·도구 카드·첨부가 웹과 같다(plan/46 §9).
4. **나머지는 웹에서**: 세 문 밖의 자리(설정·지식·스케줄…)로 가는 링크는 브라우저로 연다. 앱은 쓰는 곳이다.
5. **옛 앱은 그대로**: 앱 모드는 새 앱이 `shell ≥ 2` 를 알릴 때만 켜진다. 0.7 이하는 웹 전체를 그대로 본다.

## 3. 창

| 창 | 모양 | 하는 일 |
|---|---|---|
| 본창 | 테두리 없음 + 제목 줄 겹치기(윈도·리눅스 `titleBarOverlay`, 맥 `hiddenInset`), 최소 480×520 | 48px 아이콘 막대 · 36px 제목 줄 · 내용(세 문은 웹 뷰, 설정은 앱 화면) |
| 아바타 | 투명·항상 위·작업 표시줄 없음, 위치 기억 | 비서 얼굴, 말풍선, 말로 묻기, **먼저 건넨 말을 말한다**, 빠른 대화로 |
| 빠른 대화 | 640 폭, 내용 따라 자람(최대 520), 불투명 카드, 커서가 있는 화면 22% 높이 | 어디서든 `Ctrl/⌘+Shift+Space`, 비서 고르기, 말로 묻기, 흐르는 답, 본창에서 이어 보기 |

- **세 문 = 웹 뷰 셋**(`WebContentsView`, 처음 열 때 만들고 살려 둔다): 오가도 스크롤·입력이 그대로.
- **아이콘 막대**: 위 — 대화·소식·커뮤니티. 아래 — 빠른 대화·아바타(켜짐 표시)·알림(배지, 최근 인박스 창)·설정·나(계정 창).
- 활성 표시는 왼쪽 2px 막대(Dex), 색·글꼴·반경은 메모라 토큰(Pretendard, 브랜드 파랑).

## 4. 웹의 앱 모드

- 조건: `window.__memoraHost.shell >= 2`.
- 사이드바·머리줄(크레딧·종·테마)·휴대폰 탭 막대·인증 배너 없음. 커뮤니티 위에는 작은 탭 줄(홈·채용·기업·내 글).
- 채팅 머리줄은 폭과 상관없이 한 줄(뒤로 가기 없음 — 뒤가 없다).
- 테마는 앱을 따른다(앱이 `nativeTheme` 를 정하고 웹은 "시스템").
- 링크: 같은 문 안이면 그대로, 다른 문이면 앱이 그 문으로 옮기고, 문 밖이면 브라우저. 앱의 메인 프로세스도
  같은 규칙으로 한 번 더 지킨다(`router.push` 처럼 링크가 아닌 이동).
- 앱이 알림을 직접 띄우므로 웹의 인박스 토스트는 앱 모드에서 끈다(두 번 울리지 않게).
- 앱의 [로그아웃] 은 웹에게 맡긴다(`host.onCommand("logout")`) — 갱신하는 쪽은 여전히 웹 하나(plan/46 §2).

## 5. 실시간

앱이 `/api/notifications/stream` 을 직접 듣는다(30초 확인 대신). `message`(비서가 먼저 건넨 말·릴레이 결과) →
OS 알림 + 아바타가 말한다, `inbox` → 배지 + 알림, `room` → 배지. 끊기면 늘어나는 간격으로 다시 붙고, 5분 확인은
바닥으로 남긴다.

## 6. 설정 (본창 안의 앱 화면)

일반(로그인할 때 시작 · 시작할 때 아바타 · 테마) / 비서(아바타·빠른 대화의 비서 · 답을 소리로) / 알림(먼저 건넨 말 ·
인박스 · 메시지) / 단축키(빠른 대화 · 아바타 · 본창, 바꿀 수 있고 쓸 수 없는 조합은 그렇다고 말함) / 계정(웹에서
전체 기능 · 로그아웃) / 정보(판 · 새 버전).

## 7. 리눅스

창 위치·항상 위가 웨이랜드에서 안 되므로 X11(XWayland)로 띄운다(Geny 와 같음, `MEMORA_OZONE` 로 끌 수 있음).

## 8. 안 하는 것

- 채팅·소식·커뮤니티를 앱이 다시 그리지 않는다(§2-3).
- 웹의 나머지 기능을 앱에 넣지 않는다(§2-4).
- 서버 API 는 바꾸지 않는다. 웹은 앱 모드 표시만 더한다.

## 9. 한 것 (2026-09-28, 0.8.0)

**웹의 앱 모드** (`frontend/lib/desktop.ts`, `components/owner/AppFrame.tsx`) — 새 앱이 `shell ≥ 2` 를 알릴 때만.
- 사이드바·머리줄·휴대폰 탭 막대·인증 배너를 빼고 문 안쪽만. 소식(소식·내 글)과 커뮤니티(홈·채용공고·기업정보·
  내 활동)에는 얇은 탭 줄, 오른쪽 끝에 메시지(메신저) 단추. 대화 문은 폭과 상관없이 한 줄 머리.
- 링크: 누르는 순간 가로채 같은 문은 그대로, 다른 문은 앱이 옮기고, 문 밖은 브라우저. `router.push` 처럼 링크가
  아닌 이동은 도착한 뒤 되돌린다. 로그인·가입 화면에서도 같다.
- 앱이 시키는 일(`onCommand`): 로그아웃·그 문의 자리로 가기·메신저 열기·다시 보임(`shown`)·테마.
- 빠른 대화·아바타가 같은 대화에 말을 보태므로, 대화 화면이 다시 보이면 기록을 새로 받고 다른 곳에서 시작해
  아직 도는 답을 처음부터 따라간다(`useTurnRunner.follow`). 주소의 대화(`?c=`)가 바뀌면 열린 화면도 옮긴다.
- 인박스 토스트는 끈다(앱이 알린다). 옛 앱(0.7)에서는 아무것도 달라지지 않는다.

**앱** (`desktop/`, 0.8.0)
- 본창: 테두리 없는 창 + 운영체제 창 단추 겹치기, 36px 제목 줄(지금 자리·뒤로·새로고침, 가운데 "○○에게
  물어보기" 입구, 브라우저에서 열기) + 48px 아이콘 막대(대화·소식·커뮤니티 / 비서 얼굴=아바타 켜고 끄기·
  알림·설정·나=계정 메뉴). 활성은 왼쪽 2px 막대(브랜드 두 색). 문마다 `WebContentsView` 하나, 처음 열 때 만들고
  살려 둔다. 창 자리 기억. 나가면 막대가 접히고 로그인 화면이 창 전체를 쓴다.
- 빠른 대화: `Ctrl/⌘+Shift+Space`, 커서가 있는 화면의 22% 높이, 640 폭에 내용만큼 자람(최대 520). 비서 고르기,
  말로 묻기, 흐르는 답(가벼운 마크다운), 생각·도구 한 줄, 복사·소리로 듣기·대화에서 이어 보기. 숨겨도 답은
  메인에서 계속 흐른다.
- 아바타: 자리·접힘 기억, 비서가 먼저 건넨 말을 말하고 [답하기](빠른 대화)·[대화 보기], [글로] 단추,
  "답을 소리로" 설정을 따른다.
- 실시간: `/api/notifications/stream` 을 메인이 직접 듣는다(70초 조용하면 다시 붙음). 먼저 건넨 말 → OS 알림 +
  아바타, 인박스 → 알림(제목은 웹과 같은 문장, 누르면 그것이 있는 문 또는 브라우저의 인박스), 메시지 → 알림
  (누르면 소식 문의 메신저). 본창이 그 문을 보고 있으면 알리지 않는다. 안 읽은 수는 5분 바닥 확인.
- 설정(앱 화면): 컴퓨터를 켜면 시작·시작할 때 아바타·테마 / 곁에 둘 비서·답을 소리로 / 알림 셋 / 단축키 셋
  (눌러서 정함, 못 잡으면 그렇다고 말함) / 계정 / 정보. `userData/settings.json`.
- 리눅스는 X11(XWayland)로 뜬다(`MEMORA_OZONE` 로 끔). 글꼴(Pretendard)은 앱에 싣는다.

**검사**: 계약 테스트 18(문의 규칙과 웹과의 일치, 다리로 토큰을 읽을 수 없음, 설정 정규화, 단축키, 답의 흐름,
알림이 갈 곳). 실제로 띄우는 `test/shell.mjs` 25항목 전부 통과(로그인·앱 모드·세 문·링크 규칙·사진·알림·설정·
빠른 대화로 묻고 본창에서 이어 보기·아바타·먼저 건넨 말·60초 유지·로그아웃). 구운 설치본(`linux-unpacked`)
에서도 틀·글꼴·다리 확인.

**겪은 것**
- **테마가 웹에 닿지 않았다.** `nativeTheme.themeSource` 를 바꾸면 창 단추는 어두워지는데 틀과 웹의
  `prefers-color-scheme` 은 그대로였다(리눅스, 켤 때부터도). 그래서 앱이 직접 건넨다: 앱의 창은 `<html class="dark">`,
  웹 뷰는 다리의 `theme` 과 `theme` 명령.
- **검사가 만든 헛것을 쫓았다.** 빠른 대화의 답이 "2분 늦게" 오는 것처럼 보였는데, 앱의 창은 CSP 가 eval 을
  막아 Playwright `waitForFunction` 이 기다리지도 않고 던졌고 그것을 `.catch` 가 "안 끝남" 으로 읽은 것이었다.
  그 사이 QUIC 끄기·백그라운드 스로틀 끄기를 넣었다가 근거가 없어 되돌렸다. 턴 흐름의 25초 무응답 감시는
  잠든 노트북·바뀐 와이파이에 대비해 남겼다(서버는 15초마다 ping).
- **`refresh_reuse_detected` 1건(11:31, 앱).** 검사 중 앱을 급히 닫아 막 돌린 갱신 쿠키가 디스크에 안 쓰였고,
  다음 실행이 버린 쿠키를 내밀었다. 문이 셋이라 갱신도 잦으므로, 웹이 새 토큰을 건넬 때마다 쿠키를 바로
  내려쓴다.
- **0.7 의 안 읽은 수는 늘 틀렸다.** `/api/rooms/unread` 의 `total`(없는 필드)과 `/api/inbox?unread=true`(없는
  인자, 최근 50개를 셌다)를 읽었다. 0.8 은 `unread` 와 `new_count`.

**남은 것**
- 구글·카카오 로그인은 앱 안에서 되지 않는다(바깥 주소는 브라우저로 가고, 구글은 내장 브라우저를 막는다).
  운영은 키를 넣지 않아 지금 영향은 없지만, 켜기 전에 "브라우저에서 로그인하고 앱으로 돌아오는 길" 이 필요하다.
- 윈도·맥의 실제 화면(창 단추 겹치기·신호등 자리·단축키 충돌)은 설치본으로 한 번 더 본다.
