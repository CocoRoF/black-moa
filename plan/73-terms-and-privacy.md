# plan/73 — 이용약관·개인정보 처리방침 (대한민국 법 기준)

## 0. 요청 (2026-09-29)

- 개인정보 처리방침과 이용약관을 기본으로 넣는다. 한국에서 쓸 수 있는 강한 방식, 대한민국 법에 맞게.
- 기본 철학:
  - 비서를 어떻게 만들고 관리하는지는 **사용자의 책임**이다.
  - 오용·남용은 내부적으로 **사용자 고지 없이 제한**할 수 있다.
  - 다른 이용자를 공격하는 행위는 **차단**될 수 있다.

## 1. 판단(법적으로 버티는 선)

- **"고지 없이 제한"을 두 층으로 나눴다.** 모든 제재를 아무 통지 없이 한다는 조항은 약관규제법(제6조 신의성실, 제9조
  해지 제한)상 불공정 약관으로 무효가 될 위험이 크다.
  1. 서비스 전체에 적용되는 **자동화된 보호 조치**(속도·빈도 제한, 비용 한도, 스팸·공격·프롬프트 주입 자동 탐지,
     의심 요청의 일시 차단)는 개별 제재가 아닌 운영상 조치로서 **별도 통지 없이 상시** 운영한다. 탐지 기준도 공개하지
     않는다(이용약관 제22조).
  2. 개인에 대한 제재는 원칙적으로 사전 통지한다. 다음 경우에는 **사전 통지 없이 즉시 제한하고 사후 통지**한다
     (제23조 제2항):
     - 다른 이용자에 대한 공격이 진행 중인 경우
     - 불법정보
     - 보안 위험
     - 통지하면 증거 인멸이나 회피가 우려되는 경우
     - 수사기관의 요청

     연락이 되지 않거나 통지가 법령·수사에 반하면 통지 자체를 생략할 수 있고, 악용될 근거는 알리지 않는다
     (제23조 제3항). 이의신청은 30일, 답변은 15일(제24조).
- **다른 이용자 공격은 첫 위반이라도 정지·해지할 수 있다**(제21조 제2항). 금지 행위의 첫 항목으로 두었고, 다른
  회원의 비서에 대한 프롬프트 주입·탈옥을 명시했다(제20조 제1호).
- **비서의 책임은 만든 회원에게 있다**(제15조). 설정, 자료, 공개 링크를 누구에게 배포했는지, 비서가 회원의 설정·지시·
  승인에 따라 한 응답과 행위(메일 발송·일정·릴레이) 모두다. 회사는 도구만 제공하고 회원을 대리하지 않는다. 방문자에게
  비서의 약속·가격·일정은 회원이 확정하기 전까지 효력이 없다고 적었다(제13조 제3항). 타인의 개인정보를 등록할 권한도
  회원의 책임이다(제16조).
- **면책 조항은 전부 "회사의 고의·중과실 제외"를 단다**(약관규제법 제7조). 관할은 민사소송법에 따른 법원으로
  정했다(제14조, 회사 소재지 전속 관할 금지).
- **인공지능 기본법 제31조**(2026-01-22 시행):
  - 사전 고지: 약관 제5조, 방문자 화면의 "AI 비서"
  - 생성물 표시: 비서가 남에게 보내는 메일에 "AI 비서가 대신 쓰고 보낸 메일"
  - 비서가 사람인 척하지 않음: 방문자 지시문에 한 줄

## 2. 문서

- `backend/src/memora/assets/legal/terms.md` (38조, 11장 + 부칙·운영자 정보)
- `backend/src/memora/assets/legal/privacy.md` (17조, 작성지침 2025.4 기준 항목. 요약표·목차 같은 덧붙임은 두지 않는다 — 사용자 요청)
- 내용은 코드 전수 조사로 확인한 실제 처리만 적었다: 항목, 보유기간, 위탁, 국외 이전, 쿠키. 예를 들어:
  - 방문자 90일
  - 삭제 파일 30일
  - 접속 요청 7일
  - 감사 기록 1년
  - TTS 30일
  - 백업 28일
  - 국외 이전: Anthropic, OpenAI, Google, ElevenLabs, Voyage, Cloudflare(메일 포함), Stripe
- 자리표시:
  - `{{key}}` 는 값으로 채우고, 비어 있으면 정해 둔 대신 말을 쓴다.
  - `{{?key}}` 는 값이 없으면 그 줄째로 뺀다.
  - 운영자 정보는 관리자 [시스템 설정 → 운영자 정보]에 넣는다(`legal.*`).
  - 상호가 없으면 서비스 이름을 쓴다. 보호책임자가 없으면 대표자가 맡는다(시행령 제32조).
- 판(version) = 시행일(`legal.effective_date`, 없으면 `legal.DEFAULT_VERSION`). 관리자가 본문을 넣으면 그것을 쓰고,
  기본 원문은 [기본 이용약관 복사]로 받아 고쳐 쓴다.

## 3. 동의

- 가입(이메일, 연결 계정 마무리, 방문자 가입)은 "[필수] 만 14세 이상이며, 이용약관에 동의하고 개인정보 처리방침을
  확인했어요"를 체크해야 하고, **서버도 이 동의 없이는 가입시키지 않는다**(`terms_required`).
  - 개인정보는 계약 이행에 필요한 범위라 동의 대상이 아닌 안내로 둔다(2023 개정 개인정보 보호법 제15조 제1항 제4호).
- 기록: `users.terms_version`, `users.terms_agreed_at`(마이그레이션 0082), 감사 기록 `terms_agreed`(판 포함).
- 가입 화면의 연결(Google) 단추는 체크 후에만 눌리고 `agree=true` 를 싣고 간다. 새 계정이 만들어지면 동의를 남긴다.
- 다음 경우에는 **앱에 들어올 때 한 번** 받는다(`TermsGate`):
  - 로그인 화면에서 곧바로 만들어진 연결 계정
  - 예전 계정
  - 시행일이 바뀐 뒤

  이 창은 닫을 수 없다. [설정]은 가리지 않아 동의하지 않는 사람이 탈퇴할 수 있다. 화면이 본 판과 서버의 판이 다르면
  받지 않는다(`terms_changed`).

## 6. 남은 것(운영자가 할 일)

1. **운영자 정보 입력**: 상호, 대표자, 사업자등록번호, 주소, 연락처, 개인정보 보호책임자. 비어 있으면 처리방침의
   보호책임자 칸이 "서비스 안에서 알리는 연락처"로 남는다. 개인정보 보호법상 보호책임자 성명·연락처는 필수다.
2. **Claude 구독 계정(Claude Code OAuth)**: 각 계정 설정에서 "모델 개선에 데이터 사용"을 꺼야 처리방침의 "학습에
   쓰지 않음"과 맞는다. 소비자 구독 약관이 서비스 제공 용도를 허용하는지도 확인이 필요하다. API 키 쪽은 기본적으로
   학습에 쓰이지 않는다.
3. **유료 판매를 켜기 전에**:
   - 통신판매업 신고
   - 탈퇴해도 결제 기록 5년 보관(지금은 `purchases` 가 계정과 함께 지워진다)
   - 결제 화면의 청약철회 제한 표시(약관 제31조 제2항)
4. **백업**: 업로드 파일이 있는 SeaweedFS 가 `backup.sh` 에 빠져 있다(처리방침과는 무관하지만 복구 약속에 걸린다).
5. 방문자 IP 는 날짜를 섞은 SHA-256 이지만 비밀 키가 없다. 필요하면 서버 비밀로 HMAC 을 적용한다.

## 7. Google OAuth 브랜드 인증 (2026-09-29 저녁)

Google Cloud 콘솔의 브랜드 인증이 두 가지로 막혔다.

1. **"개인정보처리방침에 충분한 내용이 없다"** — Google 데이터가 연동 표 안에만 있었고, Google API 서비스 사용자
   데이터 정책이 요구하는 공개 내용이 없었다(접근·이용·저장·공유·제한, Limited Use 문장). 처리방침에 제8조(Google 사용자
   데이터)를 두었다.
   - 권한별 접근 데이터와 목적
   - 저장·삭제
   - 공유(응답 생성 수탁자에게만)
   - 이용 제한(광고, 범용 AI 학습, 신용 평가 금지와 사람 열람 제한)
   - Limited Use 문장(영문 그대로)과 영문 요약

   "사람이 열람하지 않음"은 실제로 집행한다: 관리자 SQL 조회 역할에서 `integration_emails`, `integration_events`,
   `network_nodes` 의 SELECT 권한을 뺐다(`dbview.PRIVATE_TABLES`, 부팅 때 적용).
2. **"홈페이지 웹사이트가 등록되어 있지 않다"** — memo-ora.com 을 Google Search Console 에서 소유 확인해야 한다.
   Cloud 프로젝트 소유 계정으로 도메인 속성을 추가하고 TXT 레코드를 넣는다(Cloudflare DNS).
   확인한 뒤 24시간 기다렸다가 다시 제출한다.

남은 판단:
- `gmail.readonly` 는 **제한 범위**다. 외부 사용자에게 공개하려면 매년 제3자 보안 평가(CASA)가 필요하다. Gmail 을 빼면
  민감 범위(캘린더, 주소록)만 남아 평가 없이 인증을 받는다(시연 영상과 범위별 사유 필요).
- 처리방침의 "학습에 쓰지 않음"은 Anthropic 쪽 설정에 달렸다. Claude 구독 계정(OAuth)은 계정마다 학습 사용을 꺼야
  한다(Google 정책은 Workspace 데이터로 범용 AI 모델을 학습시키는 것을 금지한다).
