## 1. 원칙

1. **스케줄은 원장이다.** 연락 가능 시간과 일정은 [내 정보 → 스케줄] 한 곳에서 정한다. 비서마다 켜고 끄는
   스위치는 없다 — 내 비서는 내 스케줄을 **전부 안다**(주인과의 대화).
2. **밖으로 나가는 것은 스케줄이 정한다.** 방문자에게는 **연락 가능 시간 안의 빈 시간만** 나간다. 일정의
   제목·장소·참석자는 어떤 경우에도 나가지 않는다. 누가 빈 시간을 알 수 있는지는 plan/48 의 세 단어
   (모두 공개 · 인맥에게만 · 나만)로, 연락 가능 시간 한 칸의 공개 범위가 정한다.
3. **Memora 가 캘린더다. Google 은 붙이는 것이다.** 일정은 Memora 에 직접 넣는다. Google 을 연결하면
   그 일정이 함께 보이고(읽기), 빈 시간 계산에도 들어간다. 연결하지 않아도 스케줄은 온전하다.
4. **하는 것은 주인 대화에서만.** 비서가 일정을 넣고 고치고 지우는 것은 주인이 시킬 때(주인 대화 도구)뿐이다.
   방문자는 빈 시간을 묻고 미팅을 **요청**할 수 있을 뿐, 일정은 주인이 수락할 때 들어간다(지금과 같다).
5. **시간은 주인의 시간대로.** 입력·표시·계산 모두 계정의 시간대(`users.timezone`) 기준. 브라우저 시간대가
   달라도 "15시" 는 주인의 15시다.

## 2. 데이터

### 2-1. `schedule_events` (신규)

| 열 | 뜻 |
|---|---|
| `id`, `owner_id` | |
| `title` | 일정 이름 (200자) |
| `start_at`, `end_at` | timestamptz. 종일이면 주인 시간대의 그날 00:00 ~ 다음 날 00:00 |
| `all_day` | 종일 일정 |
| `location`, `note` | 장소, 메모 |
| `busy` | 빈 시간 계산에서 이 시간을 막는가. 기본: 시간 일정은 막음, 종일 일정은 막지 않음(생일·기념일) |
| `source` | `owner`(직접) · `secretary`(주인이 비서에게 시켜서) · `meeting`(미팅 요청 수락) |
| `agent_id` | 비서가 넣었으면 그 비서 |
| `inbox_item_id` | 미팅 요청에서 왔으면 그 인박스 항목 |
| `google_event_id` | Google 에도 넣었으면 그 id — 동기화분과 겹쳐 보이지 않게 |

반복 일정은 이번에 두지 않는다. 매주 반복되는 시간은 **연락 가능 시간**이 맡고(주간 표), 일정은 한 번짜리다.

### 2-2. 연락 가능 시간

저장 자리는 그대로 `owner_profiles.data.availability_window` (`weekly`: 요일+시각 줄들, `note`) 와
`visibility.availability_window`. 읽는 곳(도구·프롬프트·프로필 블록)이 이미 이 자리를 본다 — 옮기는 것은
**화면**이다. 공개 범위 기본값은 지금과 같이 `public`.

### 2-3. Google 동기화 고침

- 종일 일정: 날짜를 **주인 시간대의 자정**으로 저장.
- `transparency == "transparent"`(한가함 표시) → `integration_events.busy = false`. 새 열.

### 2-4. 이관 (0075)

- `schedule_events` 생성, `integration_events.busy` 추가(기본 true).
- 비서마다의 설정을 원장으로: 주인의 비서 중 하나라도 [캘린더 공유 = 안 함] 이었거나 [캘린더] 능력을
  꺼 두었으면, 그 주인의 연락 가능 시간 공개 범위를 **나만**으로 둔다. 더 많이 내보내는 쪽으로 옮기지 않는다.
- 비서의 `capabilities.google_calendar`, `disclosure_policy.calendar_mode` 는 더 읽지 않는다(값은 남겨 둔다).

## 3. 비서가 쓰는 길

| 도구 | 누구 | 하는 일 |
|---|---|---|
| `calendar_list` | 주인 대화 | 기간의 일정(Memora + Google). 이름·장소·참석자까지 |
| `calendar_availability` | 주인 대화 · 방문자 대화 | 연락 가능 시간 안의 **빈 시간만**. 방문자는 공개 범위가 허락할 때만 |
| `schedule_add` | 주인 대화 | 일정 넣기 → 대화에 "일정을 넣었어요" 카드(스케줄로 가기) |
| `schedule_update` | 주인 대화 | 시간·이름·장소·메모 고치기 |
| `schedule_remove` | 주인 대화 | 일정 지우기 (Memora 일정만. Google 일정은 Google 에서) |

- 능력 스위치(`requires_capability`)·Google 연결 조건(`requires_feature`)을 뗀다. 스케줄은 원장이다.
- 빈 시간 계산은 **한 함수**(`schedule.free_slots`)가 한다. 도구와 [스케줄] 화면의 미리보기가 같은 것을 쓴다.
- 프롬프트: 주인 대화에는 "스케줄: 연락 가능 시간 …, 앞으로 7일 일정 N개(calendar_list)". 방문자 대화에는
  **공개 범위가 허락할 때만** 연락 가능 시간. 연락 규칙도 같은 규칙(지금 새는 버그를 같이 막는다).
- 먼저 말 걸기의 맥락(다음 24시간 일정)도 같은 서비스에서 — 능력 스위치 조건을 뗀다.
- 미팅 요청 수락: **스케줄에 먼저** 넣고, Google 쓰기 권한이 있으면 Google 에도(지금처럼). Google 이
  없어도 수락이 일정이 된다.

## 4. 화면

### 4-1. [내 정보 → 스케줄] (`/app/schedule`)

표준 틀: 제목 + 오른쪽 탭 **[일정] [연락 가능 시간]**.

**[일정]**
- 달력(한 달): 날짜 칸은 높이 고정, 일정은 두 줄까지 보이고 넘치면 "+N" — 올려 두면 그날 전부(공통 호버).
  오늘 표시, [이전][오늘][다음], 칸을 누르면 그날 목록이 옆에.
- [일정 추가] → 옆 창: 이름 · 종일 · 시작/끝(주인 시간대) · 장소 · 메모 · [바쁜 시간으로 표시].
- 일정 칸: 출처 표시(직접 · 비서 · 미팅 · Google). Google 일정은 읽기만(고치기는 Google 에서).
- Google: 연결돼 있으면 "Google 캘린더 · 마지막으로 가져온 때 · [지금 가져오기]", 없으면 "연결하면 Google
  일정도 여기 함께 보여요" → [연동].

**[연락 가능 시간]**
- 주간 표(요일 + 시각 줄, [정보] 에서 옮겨 온 것), 메모.
- **누가 빈 시간을 알 수 있나**: 모두 공개 · 인맥에게만 · 나만.
- **방문자에게는 이렇게 보여요**: 앞으로 5일의 빈 시간(실제 계산 결과, 방문자 도구와 같은 함수).
- 시간대 표시(계정 설정으로 가는 링크).

### 4-2. 옮기고 걷는 것

- [내 정보 → 정보] 의 [가용 시간] 칸 → [스케줄] 로 옮긴다.
- 비서 스튜디오 [능력] 의 [캘린더] 스위치, [외부인 규칙] 의 [캘린더 공유] → 걷는다.
- 비서 [지식] 탭(연결된 것): Google 줄은 메일만 남기고, **[스케줄] 줄**을 새로 —
  나와의 대화 "연락 가능 시간 · 앞으로 7일 일정 N개(Google 포함)", 외부인 "빈 시간만(공개 범위)" 또는 "알려 주지 않음".
- 사이드바 [내 정보]: 정보 · **스케줄** · 피드 · 지식 · 파일 · 인맥.
- 인박스 미팅 수락 문구: "스케줄에 넣어요(Google 에도)".
